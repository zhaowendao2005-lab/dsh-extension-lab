## D1 优先事项

1. 找到可靠的模型可见声明/提示观察方法，避免模型自述成为唯一依据。
2. 检查实际成功 YAML 的 `tools: null`，与省略字段、空数组分别比较。
3. 找出并移除 `manage_task`、`list_resources`、`read_resource`，不默认豁免。
4. 配置在进程启动前完成；有证据确认选中的 agent，不接受 fallback。
5. 验证该组合中的 DSH system 注入，当前 append 的正向证据主要来自普通会话。

若原生声明无法去除，记录具体限制并保持阻断。不能自动改成“原生工具可见但执行被拒”的产品路线。

## DSH 开发约定

- 先加载当前 `dsh-doc`，通过 Cordis Inspect 确认本次所需 Service、Event、Config 和 UI Slot 的准确契约。
- 不把 `dsh-acp`（DSH 作为 server）误当成当前客户端接入；`dsh-subagent-acp` 只是生命周期参考，不直接满足主对话适配。
- bundle 在本目录实现，通过 Plugin Manager 安装。不编辑生产 profile 的 package manifest 或 patch。
- 构造期路径/并发配置用普通字段触发重建；volatile 若需要使用，按当前文档 `.get()` 解引用并订阅变化。
- 桌面 UI 刷新不保证 Host 代码升级，安装结果与新进程/新会话验证才是生效依据。

## 首版范围

单进程单会话、有界排队、文本与 DSH 工具闭环优先。持久 resume、并发池、额度 UI、跨平台支持后置；没有实测就不宣称支持。计费统计缺失保持未知。

开发 bundle metadata、原创图标、locale、锁定依赖、构建和离线状态命令已落地。用户已授权通过 release CLI 发布 0.1 系列开发预览；包的 `private: true` 仅限制 npm registry 发布，不阻止 Git 市场分发。真实生成门禁不可由 Config 覆盖，当前不作为生产可用生成提供方。

## 生产状态

旧 `dsh-antigravity` 的停用、卸载、数据清理是独立事项，只有新方案通过且用户指定后才进行。研究文档复制归档不移动或删除旧包文件，不改变当前模型选择。
