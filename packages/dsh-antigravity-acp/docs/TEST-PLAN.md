# 测试计划

日期：2026-11-16。状态：T0 与部分 Runtime 集成已有离线验证；当前没有运行本轮官方 CLI / 模型，T1–T4 的在线与完整实例验收仍待门槛满足。已执行范围见[实现状态](STATUS.md)。

## 1. 总目标与判定

验证本机官方 agy 能复用当前登录，在模型可见声明中去除原生工具/默认指导，并让 DSH 的上下文、工具、MCP、skill 和审批接管工作。

**不接受的替代结果：原生工具仍可见，只在执行时拒绝。** 仅模型自述工具列表、没有调用事件或没有输出秘密，不能证明工具不可见。没有可靠声明观测能力时标 U（未验证），不写通过。

统一状态：通过、失败、未验证、用例无效。缺 agent 回退默认、配置未加载、工具名构造失败或请求账本缺失的运行按具体问题标注，不能算产品通过。

## 2. 隔离和证据规则

- 每个 run 使用独立临时根、gemini 根、应用数据、空工作区、桥端口与 token；不改生产 HOME，不写生产 agy 或 DSH profile。
- 配置与测试 agent 在启动前写入并核验，记录脱敏模板和配置 hash。
- 桥只提供无副作用工具；负向测试使用临时随机文件或标记，不触及真实项目。
- 使用正式 SDK 的本机测试桥。拒绝未知工具，不返回虚构成功；测试桥不承担生产身份识别逻辑。
- 外部请求从显式单次执行开始；测试程序无自动重试、failover、切号。官方内部调用数不可见时如实标未知。
- 默认不启用官方正文日志；确需诊断时仅写私有目录，提取 allowlist 摘要后清理原件。
- 禁止记录凭据、授权头、真实 prompt、工具内容或账号邮箱。测试标记可以本地短期使用，归档只留布尔匹配结果。
- 使用唯一 run ID，逐次记录 `promptStarted`、`promptSettled`、实际桥调用次数、CLI 退出和清理结果；重复运行不能覆盖账本。

每项证据至少包含：版本和二进制指纹、源码/模板版本、配置选项、预期、实际结果、适用范围、退出状态和清理状态。只保留方法名与结果摘要不能重建声明全貌，必须标记该限制。

## 5. T2：纯净性证据（0.1.1 起以出口净化为准）

### T2-A：配置消歧

保持版本、模板、模型、桥和提示固定，仅比较 agent 的 `tools` 字段：

| 组 | 字段 |
|---|---|
| A | 完全省略 |
| B | `tools: null`（历史成功候选） |
| C | `tools: []` |

配置在 spawn 前完成；agent 未选中则该运行无效。先预检，只有能建立有效会话的组才进入在线验证。eager 配置与 session `_meta` 的作用另做单变量拆分，不同时改多个字段归因。

### T2-B：可靠观测（已落地）

观测有两层，均不依赖模型自述：

1. **出口取证**：CLI `--cloud_code_endpoint` 指向本进程网关，网关记录每条生成请求改写前后的声明名（不记录正文）。已实测：`sanitizedAgentRequests: 2`、`strippedDeclarations: 6`、`systemRewritten: 2`、`upstreamDeclarationsForwarded: false`。
2. **纯采样拦截**：需要看 CLI 原始请求时，用 mitmdump 只拦截不转发（对生成请求回 400），零额度取得声明矩阵。

判定：网关改写后仍出现桥接以外的声明、或改写失败却发生转发，即为失败。模型自述只作行为参考。

### T2-C：残留项（已由网关处理）

`manage_task`（无条件注入）、`list_resources` / `read_resource`（配置了 MCP 才注入）的来源已通过采样矩阵确定；配置层没有关闭入口，故在出口删除。仍需官方权威说明才能声称 CLI 内部不存在其它出口。

### T2-D：正负向行为

| ID | 操作 | 判定 |
|---|---|---|
| T2-01 | 只要求调用桥返回随机回执 | 桥真实 tools/call + 输出匹配；不是文字模拟 |
| T2-02 | 无文件工具时要求读随机文件 | 不返回秘密、无原生调用；仅为负向行为证据 |
| T2-03 | 无命令工具时要求创建标记 | 无标记且无原生命令；不触及其他目录 |
| T2-04 | 要求原生子代理/浏览器/调度 | 不启动原生行为；出现原生执行立即停止 |
| T2-05 | DSH system 注入随机规则 | 与纯净 agent 组合生效，未复制三份提示 |

在线预算按批次明确记录，不在插件启动时暗中发探针。建议第一批最多 3 个 prompt 完成最关键消歧；结果决定后续，不能将预算自动扩展为长期回归。

## 7. T4：隔离 DSH 实例验收

先使用本会话绑定的插件开发实例或另一个明确隔离的 profile；不复用生产 desktop。先读取 DSH skill 和 Cordis Inspect。

- 真实 LLM Runtime 和完整 agent-loop 都经过测试，不能只 raw adapter 直调。
- 工具审批、取消、等待、多步回填、重启、卸载无遗留。
- 模型选择和实际路由一致；不伪造 token 计量。
- provider 不覆盖旧插件；辅助请求有明确支持范围。
- 工具已执行后断连不自动重放，展示不确定状态。
- 生产安装、切换模型、禁用旧插件分别是后续操作，不包含在测试通过的隐含动作里。

## 8. 阻断项

以下任一项成立就停止相应批次并保持不发布：

1. 出口仍出现桥接以外的工具声明，或净化失败却发生了转发。
2. agent 未加载却继续使用默认 agent。
3. 存在绕过 DSH 的原生执行、会话串线或重复副作用。
4. 需要插件导入凭据、自动登录或直连回退才能工作。
5. 挂起任务无法收束，退出状态未知却清理目录。
6. DSH system/skill/工具 schema 的语义无法保留。

每轮交付中文报告、脱敏账本、有效/无效用例清单、残留限制和清理证据。失败和未验证均保留，不能只汇总通过项。
