## 脱敏方式

三个 JSON 都由明确字段白名单重新构建，不拷贝完整结果后再删敏感字段。仅保留用例标识、配置开关、状态、布尔匹配、方法/工具名、退出码等。

不保留 `answer`、`diagnostics`、展示 title、工具参数、随机秘密、随机回执、邮箱、账号档位和授权头。`secretRevealed` 仅表示最终答案是否匹配完整随机值，不是文件操作审计。

探针文本快照不含运行时令牌值，但仍保留当时的简化实现和缺陷，且将个人程序路径改成占位符。`.txt` 后缀有意防止误认为可执行测试。原始源码 hash 在来源清单中，可与本地源对照。

## 证据缺口

- 这些是 case summary，不是原始 ACP 逐帧事件、上游请求或完整工具声明。
- JSON 没有保留模型工具清单自述原文；该自述仅能从第三轮历史报告和会话记述追溯，证据等级低于桥事件。
- 部分结果曾覆盖同名目录；最终脚本可能不是所有历史运行时版本，不能反推每次参数。
- 第三轮缺少不可覆盖的 request ledger，报告称 13 次无法从当前 8 条摘要独立核验。
- 日志和临时工作区已清理，不补造缺失证据；原报告中“全都消失”“无副作用”等全称结论不由这些摘要支持。

## 历史探针的已知问题

1. `JSON.parse` 后拿变量与字符串 `'null'` 比较，导致 JSON null 写为 `tools: null`。
2. 桥与 agent 配置在 spawn 后才写，存在加载竞态。
3. 权限放行使用名称/title/元数据的子串匹配，不能用于生产身份验证。
4. 简化 MCP server 对未知方法/工具缺少完整错误与 schema 校验。
5. 未完整追踪子进程树，未持久化所有启动参数和每次 prompt 账本。

新实现和测试必须按[测试计划](../TEST-PLAN.md)重建这些部分，不直接复制探针。

来源清单中的 hash 用于识别存档，不证明结论正确。原始文件没有被移动、编辑或删除。
