## 一、问题与边界

### 1.1 要解决什么

DSH 已经有对话、有模型、有文件工具的沙箱，但**人**在会话里要读代码、改一行、暂存、提交、切分支时，只能离开 DSH 去终端或编辑器。缺的是一个不打断会话的观察面与操作面：

| 需求 | 具体形态 | 为什么现有面板不够 |
| --- | --- | --- |
| A. 看代码 | 文件树 + 语法高亮 + 行号 + 折叠 + 搜索 + 大文件分级 | 文档预览只读且不可编辑，Markdown 之外的代码没有高亮 |
| B. 管变更 | 四组变更列表 + 单文件 diff + 暂存/丢弃/提交 + 分支切换 | 无任何 git 呈现；终端里 `git status` 需要人肉解析 |
| C. 跑命令 | 真 PTY，能跑 `npm test`、`git rebase -i`、`vim` | 宿主没有通用终端；子进程类工具是一次性的 |

三件事必须共享一个根目录与一套主题，否则就是三个插件。所以做成**一个面板、三个视图**：资源管理器 / 源代码管理 / 提交图谱，加一个可停靠的底部终端。

### 1.2 不做（并有代价）

| 不做 | 原因 | 代价（接受） |
| --- | --- | --- |
| LSP、补全、跳转定义、重构、调试器 | 需要语言服务器进程 + 每语言安装 + 与单文件 IIFE 打包冲突 | 高亮是词法级（Lezer），没有语义能力 |
| 网络 git（push/pull/fetch/clone）默认关闭 | 凭据交互、进度协议、超时取消都是独立工程；且 `git push` 会跑 credential helper 与 hooks | P2 显式开关，见 §九 |
| iframe 嵌 Host HTML | `practices.md:33` 硬规则 | 无 |
| 多根工作区（workspace folder） | 500 ms 目录缓存、路径前缀校验、状态栏分支、SCM 快照都按单根设计；多根等于把每个动作的根变成参数 | 一次一个仓库，换根 = 重新 `workspace.open` |
| 插件市场 / 主题编辑器 / 扩展宿主 | 是另一个产品 | 无 |
| 注册模型工具 | 见 §1.3 | 模型不能驱动这个面板（有意） |
| 行级暂存放 P0 | 正确性风险最高（CRLF、mode、新增文件），见 `docs/git-model.md` | P1 才做，P0 只有整文件 |
| 写 `.git/config`、自动 `safe.directory`、自动 `git init` | 安全边界（`docs/security.md`） | 用户手动处理一次 |

### 1.3 为什么这个插件不注册模型工具

| # | 理由 |
| --- | --- |
| 1 | 面板挂在 `main` 的 **keyed slot**，key 不是 `conversation` → 组件拿不到 `sessionId`（`research/dsh-surface.md`）。而工具注册是 per-session 能力，生命周期与槽位不一致。 |
| 2 | 工具一旦暴露，模型就能调 `git.discard` / `git.checkout --force` / `terminal.write`。这些动作的设计前提是"人看见确认框后点下去"，不是"模型读到 ok:true"。 |
| 3 | 模型已经有自己的文件与命令手段（沙箱内的 `read/write/bash`）。再注册一套会让**同一文件出现两个写者**，而乐观并发（`expectedVersion`）只能防冲突、不能防意图冲突。 |
| 4 | 契约里的 `invocation.kind='direct'` 是为 UI 直连设计的；工具调用需要可审计的 invocation 记录，两种语义混在一个 Remote 里会让错误处理与权限判断分叉。 |
| 5 | 拒绝理由可验证：`scripts/check.mjs` 断言 `backend/**` 不出现 `ctx.tools`/`registerTool`，review 一眼可判。 |

| A6 | 文件通道 = 自建 Host Remote（读写全套） | 官方 `ctx.remote.workspaceFiles`（只读） | 只读通道无法保存/新建/重命名/删除；两条通道读同一路径会产生两个真相（版本号、EOL、BOM 会分叉）。`files.write` 借用官方 `fs.writeText(expected)` 的乐观版本语义 | 官方通道开放写且版本语义与本契约一致 → 只保留读路径复用 |
| A7 | 图谱布局在 **Host** 计算，wire 只传 `rows[].{hash,lane,color,segments}` | 客户端算（useMemo）/ 共享 worker | 布局是纯函数但输入是全部 commits 的 parents；5 万行在渲染期算会占满主线程且无法缓存分页前缀；Host 可按 `(refs,path,maxCount,skip)` 缓存并复用已发前缀 | 布局耗时 >150 ms 或需要交互式重排（按 ref 折叠）→ 改增量布局，位置可留 Host |
| A8 | 刷新两段式：P0 = 操作后立即 + 面板可见时 1.5 s 轮询 + 窗口聚焦；P1 = `watch.*` 推送 | 一上来就 watcher / 只用轮询 | 轮询 20 行代码就能跑通且可预测；macOS `fs.watch(recursive)` 对嵌套修改只报 `rename`（实测），fd 上限也是真实瓶颈；watcher 是优化不是正确性 | watch 在 3 类仓库（1k/50k/网络盘）连续 8 h 无丢事件 → 可把轮询降到 5 s；反之 watcher 出问题 → 退回纯轮询并提示 |
| A9 | Workspace Trust 门禁：未信任 = 只读 + 硬化 git + 终端需显式确认 | 不做信任 / 只提示不拦 | `git status` 就会执行仓库配置里的 `core.fsmonitor` 等 15+ 个可执行键（2026-05 Copilot CLI、2026-08 Theia 同类 RCE）；打开别人的仓库 = 执行别人的代码 | 永不撤销。可调整的是判据（按 remote 域名、按首次打开来源），不是有无 |
| A10 | 打包 = 单文件 IIFE（esbuild `format:iife`, `splitting:false`），`react` external | 代码分割（tsdown）/ 多入口 / 资源路由 | 宿主只加载 `/plugins/<pkg>/client.js?rev=`；代码分割只有 tsdown 生成的自包含 chunk 才被支持；`/assets` 路由只服务图片（wasm/字体必然 404） | 宿主支持任意 chunk 或资源类型扩到 wasm/字体 → 可拆语言包 |
| A11 | 语言包显式白名单（构建期生成 `shared/languages.generated.js`） | 全量 `@codemirror/lang-*` / 动态 `import()` 懒加载 | IIFE 下 `import()` 会被内联成惰性闭包，**不省一个字节**；22 个官方 lang 包全装 ≈600 KB raw。白名单 = 真实仓库里出现的扩展名 | 可拆 chunk（A10 撤销）→ 改按需加载 |

| A13 | 发布 = 更新版本 + `marketplace.json` → 提交 → 打 `version-<数字>` tag → 推 main 与 tag；`lib/` 产物提交进仓库 | npm 发布 / GitHub Release / CI 构建 | 仓库既有发布流程（README）；包以 Git 子目录 `github:...#path:/packages/...` 安装，宿主直接取 `lib/`；marketplace 的 `spec` 必须浮动，不能写 `#<tag>&path:` | 迁到 npm registry 或宿主插件市场自动构建 → 重写 `docs/build.md` 的发布段 |
| A14 | 客户端状态 = 每域一个 Zustand vanilla store + 同名 datasource；`views` 禁 `useState/useReducer` | Redux / React Context / 组件内 state | 与仓库既有插件一致（`model-intelligence-test` 同构）；业务事实只能有一处，视图只订阅；datasource 是唯一 IO 出口，便于 mock 与错误契约集中 | 无。这条是包的硬约束，`check.mjs` 可判 |

## 四、关键时序

### 4.1 打开工作区（首次 / 换根）

```text
1 面板挂载 → frontend/index.js apply() 注册 slot 与 Remote（一次性）
2 Workbench 首次可见 → workspace.stores.bootstrap()
3   → datasource.call('workspace.resolve', {})            [无 sessionId]
4   Host: sessionId 缺失 → 取最近活跃会话 cwd；realpath；判定 trust
5   → {root|null, name, trust, recents, limits}
6 root === null → 空态卡片（"选择目录"按钮 → ctx.uiWorkspace.pickDirectory()
                            → workspace.open({root})），到此为止，不发任何 git 动作
7 root !== null → 并行三发（互不依赖）：
     git.status{}        → 四组 + 分支 + isHuge
     files.list{path:''} → 根目录第一页（≤5000 项）
     git.graph{maxCount:2000} → 首批 rows + hasMore
8   status.ok → 状态栏填分支/ahead-behind/变更数；SCM 视图可切
9   graph.ok  → 图谱视图预热（用户不切也要有数据，避免切过去白屏）
10 首个动作失败（E_GIT_MISSING / E_NOT_A_REPO）→ 状态栏降级徽章 + 对应视图信息卡，不回滚已成功的部分
11 记 recents（Host 内存，进程内有效；持久化到 storageDomain 见 `docs/remote-contract.md` §2 与 `docs/security.md` §12 存储清单）
```

**不变量**：`workspace.resolve` 之前不允许发任何带路径的动作；根一旦确定，后续所有动作的 `path` 都是相对路径。

### 4.2 打开并保存文件

```text
1 文件树点击 → workbench.stores.openFile(relPath)
2 已有同 path 标签 → 只切 tab（不重读）；否则新 tab {state:'loading'}
3 datasource.call('files.stat') → {size,eol,bom,binary,version,largeMode?}
4 binary → 标签变为"二进制，无法编辑"卡片（E_BINARY 或 stat.binary=true），结束
5 size > largeFileBytes.readonly(20 MB) → E_TOO_LARGE 卡片 + "仍要查看"（分页只读），结束
6 datasource.call('files.read',{path,offset:1,limit:2000}) → 首屏 2000 行
7 editor.stores 建 CM6 EditorState（按 largeMode 选扩展子集）→ 挂到 DOM
8 用户输入 → CM6 doc 变 → 与 savedDoc 比较 → dirty=true → 标签圆点 + 状态栏
9 Cmd+S：
     a. 全量读 doc（大文件按块拼）→ files.write{path,text,expectedVersion:打开时版本}
     b. ok → version 更新为返回 version；savedDoc=doc；dirty=false；状态栏 "已保存 hh:mm:ss"
     c. error.code === 'E_VERSION_CONFLICT' → 冲突对话框（三选：重新加载 / 保留本地另存 / 强制覆盖）
     d. E_TOO_LARGE/E_TRUST_REQUIRED/E_OUTSIDE_ROOT → 错误条，**不改 dirty**
```

### 4.3 暂存与提交

```text
1 用户在 SCM 视图悬停行 → 点 "+" → scm.stores.stage([path])
2 datasource.call('git.stage',{paths:[p]})   —— Host 写队列：入队 → 独占执行
3 执行 `git add -- <p>`（未跟踪文件同样 add；不递归目录，逐 path）
4 ok → {staged,seq}; 旧 seq 丢弃；立即再发 git.status{seq} 刷新四组（不复用返回值猜状态）
5 用户输入提交信息 → 空串/纯空白 → Commit 按钮 disabled（不是点了才报错）
6 Cmd+Enter → scm.stores.commit()
7 datasource.call('git.commitCreate',{message})  → `commit -F -`（stdin 传 message）
8 ok → {hash,seq} → 清空输入框 → git.status → 四组清空 + 状态栏变更数归零
9 graph 已加载过 → 图谱顶部插入虚拟未提交节点消失、新提交行 prepend（不整页重拉）
10 失败（pre-commit hook 拒绝 / 空暂存区 / GPG 失败）→ 错误条显示**过滤后的 stderr 首 8 行**，输入框内容保留
```

**不变量**：commit 成功后**不自动 push**（P2 才有）；失败时**不改**暂存区（不自动 unstage）。

### 4.4 切分支后的全量刷新

```text
1 状态栏分支名 → 分支菜单（git.refs）→ 选目标 → 未提交数 >0 时先弹"工作区不干净"对话框
2 用户确认强制 / 或先 stash（P1）→ git.checkout{ref,force?}
3 执行成功 → Host 使这些缓存失效（按 root 维度，一次性）：
     status 快照、files.list 全部目录缓存、git.log/graph 分页缓存、git.commit 详情缓存
4 客户端 seq/version 处理：分支切换后所有在途响应都过期 → workspace.stores.bumpEpoch()
     → 旧 epoch 的响应一律丢弃（不是丢弃旧 seq，而是整代作废）
5 并行重发：git.status、files.list('')、git.graph{maxCount,skip:0}
6 打开的编辑器标签逐个 files.stat：
     version 未变 → 保留 CM6 state
     version 变  → 标 "磁盘已变" 徽章，不自动重载（用户的未保存内容不能丢）
     path 不存在 → 标签标 "已删除（在 <旧分支>）"，只读
7 终端**不重启**（PTY 有自己的 cwd 与 shell 状态；分支切换不影响进程）
```

### 4.5 面板关闭再打开（终端保持）

```text
1 用户切到对话视图 / 关闭面板 → panel 卸载
   保留：stores 全部数据、CM6 EditorState（在 store 里持有）、终端 xterm 实例与 offset
   停止：status 轮询、graph 分页请求；不 stop 终端（PTY 继续跑，缓冲继续攒）
2 重开面板 → runtime 挂载 → 按 store 恢复视图（不重放动作）
3 终端恢复：
     a. terminal.list → 与本地标签对账（Host 端已回收的标灰 + "已结束"）
     b. 每个标签 terminal.poll{offset} → 补发离线期间的输出（dropped=true 时提示"输出被截断"）
     c. 继续 120 ms 轮询
4 一次对齐：workspace.state（根是否被 Host 侧改变、trust 是否变）→ 不一致则整代作废重拉
```

## 五、数据与状态

| 域 | 真相在 | 客户端只存 |
| --- | --- | --- |
| workspace | Host（root/trust/git 摘要） | 最近一次响应 + epoch |
| files | Host（目录内容、文件版本） | 展开态、选中、排序、500 ms 缓存镜像 |
| editor | CM6 `EditorState`（正文）+ Host（磁盘版本） | 标签元数据、dirty、光标、滚动、largeMode |
| scm | Host（status 快照 + seq） | 展开态、提交草稿、队列可视化 |
| graph | Host（布局 + 分页） | 可视窗口、滚动锚、选中、过滤词 |
| diff | Host（hunk 数据） | 折叠区间、滚动位置 |
| terminal | Host（PTY + 缓冲） | 标签元数据、offset、面板高度 |
| notice | 客户端（纯呈现） | 确认框、toast、错误条 |

三条铁律：

1. **Host 是唯一真相**。客户端不得从两次响应"推导"出第三次的事实（例如不能从 `git.stage` 的 `{staged}` 反推四组列表，必须重发 `git.status`）。
2. **`seq` / `version` 单调，旧的一律丢**。`git.status`、`git.graph`、`files.list`/`files.read` 的响应必须带 seq/version；分支切换、根切换用 **epoch** 整代作废，比逐条比对更不容易漏。
3. **乐观 UI 只用于呈现态**：标签高亮、树展开、终端标签关闭、输入框草稿。业务动作（暂存/提交/写盘）**不允许**先改 UI 再补事实；失败必须回滚呈现态并出错误条。

## 八、安全边界摘要

完整规则见 `docs/security.md`。这里只有六条不可协商的：

1. **未信任 = 只读**。写文件、git 写动作、起终端全部 `E_TRUST_REQUIRED`；信任状态存 `storageDomain: workspace_ide/trust`，不进仓库、不进 wire 的任意路径。
2. **只读 git 一律硬化**：`--no-optional-locks -c core.fsmonitor=false -c core.hooksPath=<空目录> -c core.pager=cat -c diff.external= -c credential.helper= -c core.askPass= -c core.sshCommand=` + `GIT_TERMINAL_PROMPT=0`；**不清 `filter.*`**（会破坏 git-lfs）。
3. **写路径沿用用户配置**：不替用户关 hooks（那会让 lint 静默失效）；设置里给"运行 git hooks"开关，关掉时才注入空 `hooksPath`。
4. **路径校验在 Host**：`path.resolve(root, rel)` → `realpath` → 前缀比较带 `/` 边界；越界 `E_OUTSIDE_ROOT`。
5. **不改用户 `.git/config`**、不写全局 `safe.directory`、不自动 `git init`/`git add -A`、不加 `--force`；临时覆盖一律 `git -c`。
6. **凭据零接触**：不读 `~/.git-credentials`、不实现 credential store；网络动作默认关闭，开启也必须由人点击。

## 十一、与契约的差异（已复核：4 条全部并入契约 v2）

| # | 初版缺口 | 契约 v2 实际 | 与初版建议的差别 |
| --- | --- | --- | --- |
| 1 | 非仓库目录需要「初始化仓库」 | 新增 `git.init {defaultBranch?}` → `{seq}`，前置 `trust==='trusted'` + UI 二次确认 | 签名不带 `path`（根目录只能由 Host 解析，wire 不接受任意绝对路径） |
| 2 | 未跟踪文件的 diff 语义 | 新增 `target:{kind:'untracked', path}`，Host 内部走 `diff --no-index /dev/null <path>`（退出码 1 视为成功），返回 `status:'A'`、hunk 全 `+` | 采纳「Host 侧实现」而不是「客户端用 `files.read` 合成」——后者会丢掉 `core.autocrlf` 等归一语义 |
| 3 | `terminal.create` 的未信任确认没有通道 | 契约明确：**Host 一票否决**，UI 确认只是 UX；不引入 `confirmTrusted` 凭据 | 采纳了更安全的那一支：未信任目录就是不能开终端，UI 必须提前说清 |
| 4 | 分支切换后「整代作废」缺信号 | `git.status.repoEpoch`（`sha1(root\|branch\|HEAD sha\|unborn)` 前 12 位）+ `workspace.state.git.repoEpoch`；响应 epoch 不等于当前值即丢弃 | 采纳；比逐个比 `branch.sha` 可靠（`git init`、切根目录也都覆盖） |

> 契约变更记录见 `docs/remote-contract.md` §9。此后任何"实现撞上契约缺口"都必须先补契约再写代码，不许在实现里私自定义字段。
