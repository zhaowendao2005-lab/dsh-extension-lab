# 工作区 IDE 右栏化方案 v2：内嵌标签页 · 拖动分栏 · 两栏工作台

> 状态：**v2 已实现（2026-11-15）**，默认取值按 §8 的「建议」列；浏览器运行验证仍需单独批准。
> 实现落点：右栏 tab + 内部标签/分栏（`stores/layout.stores.js`、`service/split.js`、`views/workbench/*`），提交图谱/改动改为标签页，Host 根目录按会话解析。
> 依据：宿主运行时 DSH 0.2.2-rc.1（app.asar 内 `dsh-client-ui-sidebar-right` / `-layout` 源码）+ 本仓库右栏样板（`dsh-plugin-dev-sandbox/frontend/index.js:47-53`、`model-intelligence-test/frontend/index.tsx:59-65`）。

## v1 → v2 改了什么

| 主题 | v1（已否决的固定分区） | v2（本方案） |
| --- | --- | --- |
| 工作台内部 | 活动栏 + 导航面 + 编辑区 + 底部终端，位置固定 | **左栏（文件/搜索）+ 工作区（标签行 + 内容区）** 两栏；内容区可再分栏 |
| 提交图谱 / 当前改动 | 左栏的活动栏视图 | **工作区内的标签页**，可关闭、可拖去分栏 |
| 内部标签 | 只有编辑器文件标签 | **统一标签模型**：文件、diff、提交图谱、当前改动、设置（终端见 Q6） |
| 关闭标签 | 只能点 × | × / 中键 / 右键菜单「关闭当前 / 关闭其他 / 关闭所有」 |
| 分栏 | 无（只有底部终端高度可拖） | **把标签拖到内容区四边/中心分栏**（左右、上下、嵌套），VS Code 式 |
| 左中右三栏 | v1 设想导航 + 编辑 + 右侧详情 | **不做**：外层只两栏；详情/图谱/改动都进标签页，靠分栏并存 |

## 0. 一句话结论

工作台仍然是 **DSH 右栏（rightbar）的一个宿主 tab**；但它的内部改为一个**迷你的 VS Code 工作台**：左边是可收起的文件/搜索栏，右边是带标签行的工作区；标签可关闭、可右键批量关闭、可拖到内容区四边产生左右/上下分栏；「提交图谱」「当前工作区改动」不再是左栏视图，而是两个可关闭的标签页。

```text
DSH 右栏（宿主 tab 条：聊天 | 源代码管理 | 工作台）
┌─ 工作台（宿主右栏的一个 tab）─────────────────────────────────┐
│ 工具栏 30px：▾ repo-name  main*        [⌕] [⑂] [±] [>_] [⋯]  │
├──────────────┬──────────────────────────────────────────────┤
│ 左栏（可收起）│ 分栏组 A                                     │
│ [文件][搜索]  │ ┌ a.ts × │ b.ts × │ 改动 × ┐                 │
│ ├ src         │ │                                      │     │
│ │ ├ a.ts      │ │          编辑器 / 图谱 / 改动           │     │
│ │ └ b.ts      │ └──────────────────────────────────────┘     │
│ └ package.json│ ═══════════ 分隔条（可拖）══════════════════  │
│               │ 分栏组 B（把「图谱」tab 拖到 A 的下边缘产生）  │
│               │ ┌ 提交图谱 × ┐                               │
│               │ │  提交图    │                                │
│               │ └────────────┘                               │
├──────────────┴──────────────────────────────────────────────┤
│ 状态栏 22px：main*  ●3 个变更   Ln 12, Col 3   UTF-8   TS    │
└──────────────────────────────────────────────────────────────┘
```

## 2. 宿主右栏事实（不变，v1 已核）

| 事实 | 证据（宿主包） | 含义 |
| --- | --- | --- |
| `main` 面板不绑会话；**有全局面板时右栏不渲染** | `dsh-client-ui-sidebar-right/src/client/index.ts:170-183` | 工作台必须做成右栏 tab 才能与对话并存 |
| 右栏 tab body 是 session 作用域 | `contract/slots.ts:61-66`（`scope:'session'`） | 每个会话一个工作台、一个根目录 |
| tab 类型公开注册：`id/kind/multiple/keepMounted/title/guide` | `tab-registry.ts:96-141` | 入口 + 生命周期都走官方扩展点 |
| 右栏宽度：最小 300、默认 45%、上限 70%、中栏保底 400 | `layout/src/client/columns.ts:13,29-33` | 内部布局必须在 300px 可用 |
| 宿主左栏：`Mod+B`、<1024 自动收起、<768 抽屉 | `layout/src/client/columns.ts:23-27` | R3 直接用 |
| 右栏支持分栏/浮动/全屏/按会话持久化 | 宿主包 `README.zh.md` | 我们只做**工作台内部**的分栏，不碰宿主停靠 |

> 注意：宿主右栏本身也能被用户拖成两格（dockkit 分栏），那时每个格子里各有一个「工作台」宿主 tab。我们内部的分栏是独立的一层，二者互不冲突，但文档里要说清「两层 tab / 两层分栏」。

## 3. 交互设计

### 3.1 三层结构

```text
L1  DSH 右栏 tab 行（宿主）：聊天 | 源代码管理 | 工作台        ← 关掉「工作台」= 关整个工作台
L2  工作台内部 tab 行（我们）：a.ts | b.ts | 提交图谱 | 改动    ← 关掉 = 关一个编辑器/视图
L3  工作台内部内容区分栏（我们）：组 A | 组 B（每组自带 L2 tab 行）
```

| 层 | 谁拥有 | 关闭语义 | 视觉区分 |
| --- | --- | --- | --- |
| L1 | 宿主 | 关闭整个工作台（宿主会调我们的 close handler） | 宿主 chip 风格（圆角胶囊、无图标） |
| L2 | 工作台 | 关闭一个文件/视图；脏文件先确认 | 编辑器标签风格：上圆角、活动标签与内容区同底、文件名 + 类型图标 + 脏点 + × |
| L3 | 工作台 | 组分隔条拖比例；组内清空后组自动合并 | 组间 1px 边线 + 4px 拖拽热区 |

**避免混淆的三条硬规则**：

1. L1 的 tab 永远只有一个叫「工作台」；内部开的文件不会变成宿主 tab，宿主 tab 条不随内部标签增长。
2. L2 的标签行只画在内容区上方（左栏顶部不重复画），且样式与 L1 明显不同（见 3.15）。
3. 内部「关闭所有」只关 L2 当前组，**永不关掉 L1 工作台**；要关整个工作台用宿主 × 或 ⌘W（宿主命令）。

### 3.2 入口与打开路径

| 入口 | 位置 | 行为 |
| --- | --- | --- |
| 宿主开始页卡片「工作台」 | 右栏 `+` → 开始页 | 宿主原生 openTab，展开右栏并聚焦 |
| 快捷键 `⌥⌘⇧E/F/G/R` | 全局 | 打开/聚焦工作台，并把对应内容开成当前组的活动 tab（E=文件、F=搜索、G=改动、R=提交图谱） |
| 工具栏 `⑂` / `±` | 工作台工具栏 | 打开「提交图谱」/「当前改动」单例 tab（已开则聚焦） |
| 状态栏「⑂ main」「● 3 个变更」 | 工作台状态栏 | 点击分别打开图谱 / 改动 tab |
| 欢迎页按钮 | 空组内容区 | 打开文件… / 查看改动 / 提交图谱 / 新建终端（若 Q6 采纳终端 tab） |
| 左栏文件树 | 左栏 | 单击预览打开、双击固定（见 Q5）；目录单击展开 |
| 命令面板 `/ide` | 对话输入框 | P2 可选 |

**打开落点规则**（VS Code 式）：

1. 没有分栏时，开在当前唯一组。
2. 有多个组时，开在**上次获得焦点的组**；若该组是图谱/改动等单例视图，仍然开在该组（文件与视图可共存于一组）。
3. 文件 tab 已存在于任意组 → 聚焦那个组并激活它，不重复开。
4. 单例视图（图谱/改动/设置）已存在于其它组 → 聚焦那个组，不搬动。
5. 打开新文件不改变现有分栏结构；要并排看两个文件，用户拖 tab 或右键「拆分」。

### 3.3 默认工作区（v1 结论保留）

Host 解析优先级：**该会话手动覆盖值 > `session.header.cwd` > lastRoot > 无**。首次打开 = 会话 cwd；用户在该会话点过「打开文件夹」则记住覆盖值；「⋯」菜单可「恢复会话默认工作区」。新增 Host 动作 `workspace.useSessionRoot` 与字段 `source`（详见 4.7）。

### 3.4 外层两栏布局

| 区域 | 宽/高 | 行为 |
| --- | --- | --- |
| 工具栏 | 30px | 根目录 chip（点击出工作区菜单）、分支、快速打开、图谱、改动、终端、⋯ |
| 左栏 | 默认 `clamp(180px, 30cqi, 260px)`，可拖 160–320 | 头部 [文件][搜索] 分段 + 收起按钮；主体是文件树/搜索结果；收起后宽 0 |
| 工作区 | 剩余宽度 | 一个或多个分栏组；每组 = 标签行（28px）+ 内容区 |
| 状态栏 | 22px | 分支、变更数、光标、缩进/EOL/语言；窄态精简 |
| 终端 | **建议按 Q6 做成 `term:<id>` 标签页**（与分栏统一）；若保留底部面板则 0/180–320、窄态抽屉 | Q6 |

窄态（<520px）时左栏变抽屉（默认收起），工作区占满；工具栏压缩为「‹ 返回 + 当前文件 + 3 个图标 + ⋯」。

**外层只有两栏**：文件/搜索是左栏，其余一切（编辑器、diff、图谱、改动、设置、终端）都是工作区里的 tab；详情面板不再单开第三栏，而是「另开一个 tab 或分栏」。

### 3.5 内部标签页模型

| 类型 | tab id | 单例 | 打开来源 | 关闭后 |
| --- | --- | --- | --- | --- |
| 文件 | `file:<相对路径>` | 否 | 文件树、快速打开、最近文件 | 未保存先确认；移除 tab |
| diff | `diff:<target>` | 否 | 改动 tab 行点击、图谱提交、冲突 | 移除 |
| 提交图谱 | `view:graph` | 是 | 工具栏 ⑂、状态栏分支、欢迎页、快捷键 | 移除，可从入口重开 |
| 当前改动 | `view:changes` | 是 | 工具栏 ±、状态栏变更数、欢迎页、快捷键 | 移除，可重开 |
| 设置 | `view:settings` | 是 | ⋯ 菜单 | 移除，可重开 |
| 终端（若 Q6 采纳） | `term:<id>` | 否（多实例） | 工具栏 >_、快捷键、欢迎页 | 关 tab = 杀 PTY（确认策略见 Q6） |

规则：

- **每个 tab 有唯一 id**，同一 id 在全工作区只存在一份；文件按路径去重，diff 按目标去重。
- **活动组**：焦点在哪个组，哪个组就是 `activeGroup`；所有「打开」落到活动组。
- **预览标签（建议 P0；若 Q5 选「保持双击才打开」则跳过）**：文件树单击 → 斜体标题的预览 tab，再次单击替换上一个预览 tab；双击或编辑后转正式 tab。
- **脏标记**：文件名后 8px 圆点；批量关闭/会话切换前要处理（4.9）。
- **标题**：文件用 basename；diff 用「文件名 (diff)」；图谱「提交图谱」；改动「改动」+ 变更数徽标。
- **tab 行**：高 28px，横向滚动不折行；活动 tab 底与内容区同色、上沿 2px 品牌色；hover 显示 ×；中键关闭；溢出时右侧出现「全部标签」下拉（P1）。

### 3.6 标签右键菜单

在 L2 的 tab 上右键（也在 tab 行的空白处右键，作用对象 = 该组）：

| 菜单项 | 作用域 | 快捷键提示 | 脏文件处理 |
| --- | --- | --- | --- |
| 关闭当前 | 被点的 tab | `⌥⌘⇧W`（内部，见 3.11） | 单文件确认 |
| 关闭其他 | 该组除被点 tab 外全部 | — | 批量确认 |
| 关闭所有 | **该组全部 tab**（不是所有组） | — | 批量确认 |
| 分隔线 | | | |
| 拆分 → 向右 / 向左 / 向下 / 向上 | 被点 tab | — | 作为拖拽的无障碍替代 |
| 分隔线 | | | |
| 复制路径 | 仅文件 tab | — | — |

细节：

- 批量关闭确认框列出「N 个未保存文件」，按钮三选一：**全部保存并关闭 / 放弃并关闭 / 取消**（P0 至少要有后两个；保存失败则保留 tab 并出错误条）。
- 菜单在根容器内绝对定位，贴边自动翻转，`Esc`/点外部/失去焦点关闭；`role="menu"`，↑↓/Enter 键盘可用；`Shift+F10` 或右键打开。
- 「关闭其他」在只有 1 个 tab 时置灰；「关闭当前」「关闭所有」始终可用（后者关完该组并回到欢迎页）；单例视图没有额外限制。
- 「关闭所有分栏」不放在单个 tab 菜单里：它属于 tab 行右侧「⋯」与工具栏「⋯」的组级操作。
- 关闭后若组为空：组数 >1 → 合并掉该组；组数 =1 → 显示欢迎页（不是关闭工作台）。

### 3.7 拖动分栏（VS Code 式）

**手势**：在 L2 标签上按下并移动超过 4px → 进入拖拽；出现跟随指针的 tab 幽灵；所有组的内容区进入「投放区」状态；松开完成，`Esc` 取消。点 × 按钮不进入拖拽。

**五区判定**（对指针所在组的内容矩形）：

```text
┌─────────────────────────────┐
│            上 25%            │  → 上下分栏，新组在上
├──────┬───────────────┬──────┤
│ 左25%│     中心       │ 右25%│  → 左右分栏 / 移动
│      │  （移动到本组） │      │
├──────┴───────────────┴──────┤
│            下 25%            │  → 上下分栏，新组在下
└─────────────────────────────┘
```

| 投放位置 | 结果 |
| --- | --- |
| 左/右边缘 | 该组变成左右分栏，被拖 tab 进新组（原来同组则移出） |
| 上/下边缘 | 该组变成上下分栏 |
| 中心 | 移动到该组，插到活动 tab 之后；同组内为「重排」（P1 支持拖动排序，P0 落到末尾） |
| 组外空白/窗口外 | 取消，tab 回到原位 |

**约束**：

- 最多 **4 个组**（2×2 的等效容量；树结构允许左右+上下嵌套，但总组数封顶）。达到上限时所有边缘区置灰并提示「已达 4 个分栏」。
- 新组最小 **180×140px**；放不下时对应方向的边缘区置灰（不误伤：置灰区不可投放）。
- 拖拽期间不改变布局，只在松开时一次性提交（避免抖动与中间态）。
- 拖动中显示目标区高亮（品牌色 12% 底 + 2px 描边 + 中央文案「拆分到右侧 / 移动到此处」）。
- 拖拽到同一组的同一位置 = 无操作；拖拽被拖 tab 所在组的唯一 tab 到边缘 = 拆分（合法）。
- 组变空自动合并：分隔条所在的父节点塌缩，兄弟组占满空间；连续关闭直到剩 1 组时回到单组。
- 分隔条：4px 热区（负 margin 扩到 8px），拖动改比例，比例限制 0.2–0.8，双击恢复 50/50。
- 拖拽期间禁用宿主的右栏宽度拖拽（指针已捕获，天然不冲突）。

**与宿主的边界**：这套拖拽只在工作台内容区生效，不会触发宿主 dockkit 的 tab 移动/分栏；宿主的分栏仍只发生在 L1（右栏顶部 tab 条），两者互不影响。

### 3.8 左栏（文件 / 搜索）

| 项 | 值 |
| --- | --- |
| 头部 | 26px：[文件][搜索] 分段 + 收起箭头 + 刷新；不再有活动栏竖条 |
| 文件树 | 保持现有行高 22、缩进 12、单击选中/预览打开、双击固定、右键菜单（重命名/删除/复制路径/新建） |
| 搜索 | 保持现有 `files.search`；结果行点击 → 在工作区开文件 tab（预览） |
| 收起 | 收起后宽 0，工具栏出现「☰ 打开文件栏」；`⌥⌘⇧B` 同效；窄屏 <520 默认收起并变抽屉 |
| 持久化 | 宽度/收起状态写布局 v2；按浏览器（几何）而非按会话 |

### 3.9 图谱 / 改动 / diff / 设置这四个 tab

**提交图谱（`view:graph`）**

- 占满所属组；顶部一条 28px 工具条（过滤 refs/作者/消息 + 刷新），下面是泳道图 + 提交行。
- 宽度 <520：隐藏作者、时间列，保留泳道 + subject + hash；行高 26。
- 单击提交 → 打开「提交详情」diff tab（在当前组或按用户拖拽分栏）；右键「在右侧分栏打开」P2。
- 状态保留：滚动位置、选中提交随 tab 存在；切走再回来不重置。

**当前改动（`view:changes`）**

- 提交框 + 四组变更（已暂存/未暂存/未跟踪/冲突）+ 每行 stage/unstage/discard + 打开 diff。
- 行点击 → 开 `diff:` tab（在活动组）；行内「在分栏打开」P2。
- 变更数为 0 时显示空态；未信任只读。
- 这个 tab 与宿主右栏可能已有的「源代码管理」tab 功能重叠（Q13）。

**diff tab**

- 宽 ≥560：左右两栏；<560：单栏 unified；行高 20；导航上/下一处（F7）。
- 关闭即关闭 diff，不影响源文件 tab。

**设置 tab**

- 根目录、信任、刷新策略、编辑器偏好、快捷键说明；从 ⋯ 打开；单例。

**欢迎页（空组）**

- 显示工作区名/根路径 + 最近文件 + 按钮「打开文件 / 查看改动 / 提交图谱 / 新建终端」；第一次打开工作台时只有它。

### 3.10 会话切换 / 收起 / 关闭 / 刷新

| 事件 | 行为 |
| --- | --- |
| 切到 B（B 无工作台 tab） | A 的 body 由 `keepMounted` 保留并 `visible=false`：停轮询/watch/键盘；B 显示宿主开始页 |
| 切到 B（B 有工作台 tab） | B 的 body 变可见 → resolve B 的根 → 刷新改动/图谱；**内部 tab 与分栏布局按会话恢复** |
| 切回 A | A 变可见 → resolve 回 A 的根 → 刷新；A 的内部布局与未保存文件原样 |
| 收起右栏 | 宿主隐藏整列；body 仍挂载、`visible=false` → 停一切轮询；PTY 保留 |
| 关闭工作台（L1） | 宿主 close handler（同步）→ 快照所有组里的脏文件 → 释放 store/xterm；PTY 不杀 |
| 关闭内部 tab（L2） | 只影响该 tab/该组；脏文件确认；组空则合并/欢迎页；**不关 L1** |
| 刷新页面 | 宿主右栏收起；L1 tab 由宿主 localStorage 恢复；L2 布局由我们按会话恢复；编辑器内容不恢复（现状） |
| 右栏全屏 / 浮动 | 宿主行为；内部布局不变（宽度变大只会解锁更多分栏方向） |

### 4.1 宿主注册（与 v1 相同）

### 4.2 每会话运行时 / 可见性 / keepMounted

- **keepMounted: true**：切会话/切宿主 tab 时 body 不卸载，内部 tab 与未保存编辑器状态保留。
- 隐藏（`visible=false`）时：停 SCM 轮询、git watch、终端 poll、所有 window 级监听；恢复可见时重新 resolve 根并按需刷新。
- runtime Map：`sessionId -> { client, stores }`；插件 dispose 与宿主 close handler 里释放。
- 宿主 rehydration：`tab.actions.bindCommands({ refresh })` 接入右栏「刷新当前页面」。

### 4.3 工作台状态模型（新增 layout 域）

#### 4.3.1 持久化

- key：`workspace_ide/ui.workbench.v1.<sessionId>`（按会话；宿主右栏布局也是按会话的）。
- value：`{ version, tree, groups, tabs, activeGroup, nav }`；不存编辑器正文、不存未保存内容（P2 可用 sessionStorage 快照）。
- 写入：布局变更后 200ms 防抖；关闭/拆分/合并/分隔条结束时立即写。
- 恢复：resolve 到根之后执行；校验（tab id 合法、文件在根内、组非空、树叶子都在）→ 丢弃坏节点、合并空组；全部无效则欢迎页。
- 上限：tab 数 ≤ 40；树深度 ≤ 3；组数 ≤ 4；超限丢弃尾部并保留活动 tab。

### 4.4 拖拽实现（DnD）

不引第三方库，用 pointer events 自己实现（HTML5 DnD 的拖影/触摸/取消都不可控）：

```text
pointerdown(tab) ──> 记录候选（tabId, fromGroup, x0, y0）
      │ 移动 < 4px 或 pointerup  → 当普通点击（激活 tab）
      │ 移动 ≥ 4px              → drag = { tabId, fromGroup, x, y }
pointermove
      ├─ 更新幽灵位置（相对 .wid-root 的 absolute，不进 fixed）
      ├─ 命中测试：elementFromPoint 找 [data-wid-group]（幽灵 pointer-events:none）
      ├─ 算 zone：groupRect 的 25% 边缘 → left/right/top/bottom，其余 center
      ├─ 校验 canSplit/canMove（4.5）→ 不可放时 target=null、不显示高亮
      └─ 只在目标变化时写 store（降低重渲染）
pointerup ──> zone 有值：splitTab / moveTab 一次提交；无值：取消
Esc / pointercancel / 窗口失焦 ──> 取消
```

实现要点：

- 抓取用 `setPointerCapture` + 窗口级 `pointermove/pointerup`；拖拽期间 `document.body.style.cursor = 'grabbing'`（结束恢复）。
- 幽灵是根容器里的 absolute 元素（tab 胶囊 1:1，90% 不透明，`pointer-events:none`），位置用 `clientX/Y - rootRect.left/top` 计算，**不出右栏**。
- 组矩形在拖拽开始时取一次 + 滚动/ResizeObserver 失效时重取；拖拽中不读 layout 之外的 DOM。
- 拖到组外：不显示高亮，松开取消。
- 组边缘判定用「内容区矩形」而不是标签行；中心区包含标签行下方全部。
- 拖拽期间禁用文本选择（`user-select:none`）与 CM6 的 pointer 事件（幽灵覆盖区域自然拦截）。
- 无障碍替代：右键「拆分 → 方向」调用同一 `splitTab`；不依赖拖拽也能完成全部分栏。
- P0 只做「跨组移动 + 四向拆分」；组内拖动排序 P1（同一套 pointer 逻辑，按标签行 x 计算插入位）。

### 4.5 分栏树与约束

树与组分离（`tree` 只存结构；`groups` 只存内容），这样移动/关闭不重排整棵树。

纯函数放 `frontend/service/split.js`（无 IO、可单测，但测试需批准）：

| 函数 | 作用 |
| --- | --- |
| `leaves(tree)` | 按视觉顺序返回 `{ id, path }`；用于计算组序号与最小尺寸 |
| `splitLeaf(tree, groupId, dir, newGroupId, ratio)` | 叶子 → `split(dir, a=原叶子, b=新叶子)`；dir 由 zone 决定（left/right → row；top/bottom → column，左右/上下顺序） |
| `removeLeaf(tree, groupId)` | 移除叶子并把父节点替换为兄弟；根就是叶子时返回 null |
| `updateRatio(tree, path, ratio)` | 分隔条拖动 |
| `canSplit(rect, zone, minW, minH)` | 结果尺寸 ≥ 最小，或组能再分 |
| `canMove(tabId, targetGroupId)` | 单例已在别组、目标已达？等业务规则（workbench 层） |

约束常量：`MAX_GROUPS = 4`、`MIN_GROUP_W = 180`、`MIN_GROUP_H = 140`、`SPLIT_MIN_RATIO = 0.2`、`SPLIT_MAX_RATIO = 0.8`。

- 组尺寸通过每组的 ResizeObserver 写入 store（只存宽高，不参与渲染循环）。
- `canSplit` 用测得尺寸：新组宽 = 当前宽 × (1-ratio)（或 0.5）≥ 180；高同理。分栏方向放不下 → 该 zone 不可投放/菜单项禁用 + tooltip 说明。
- 新增组默认比例 0.5（拖到边缘时按指针位置取 0.3–0.7，用户随后可拖）。
- 关组：`removeLeaf` + 删除 group + 校正 activeGroup；只剩一组时内容区按欢迎页处理。
- 分隔条渲染在树容器里，`pointerdown` 捕获 → `pointermove` 按父容器像素换算 ratio → `pointerup` 落库；双击 0.5。
- 不做宽高过渡动画；布局变化后 CM6/xterm 通过 ResizeObserver 自行 fit。

### 4.6 编辑器 / 终端在多组里的生命周期

- 组内只挂**活动 tab** 的内容；非活动 tab 卸载 DOM，`EditorState`（文档、选区、滚动锚点）缓存在 `EditorStateCache: Map<tabId, EditorState>`，重新激活/移动组时用缓存重建 view（滚动位置另存 `scrollTop`）。
- 脏标记与 `version` 在 editor store，与 view 是否挂载无关；保存用缓存 state 序列化即可，不要求 view 在场。
- 同一文件不会同时出现在两个组（tab 唯一）；移动 = 从一个组删除 + 另一个组插入，缓存随 tabId 走，不重读文件。
- 关闭/切换宿主 tab 时，脏文件从缓存序列化做快照（4.9）。
- 若 Q6 采纳「终端 tab」：xterm 随 tab 卸载销毁，但 PTY 与环形缓冲在 Host/terminal store，重挂时按 `offset` 续读（现有机制），无需特判。
- 性能：每组最多 1 个 CM6 view；图谱/改动单例各 1 个；避免现有实现里「所有已打开文件同时挂 CM6」的做法。

- L1 与 L2 的视觉区分：L2 用「上圆角 + 活动标签与内容同底 + 上沿 2px」，L1 由宿主控制（胶囊）；我们的 tab 行不加外框、不加阴影，避免看起来像第二层宿主 chrome。

### 4.9 关闭安全与脏数据

| 场景 | 行为 |
| --- | --- |
| 关闭内部 tab（单） | 脏文件 → 现有确认框「放弃并关闭」；取消则不动；确认后从 EditorState 释放 |
| 关闭其他 / 关闭所有 | 收集本组脏文件 → 批量确认（全部保存并关闭 / 放弃并关闭 / 取消）；保存失败保留 tab 并出错误条 |
| 关闭工作台（L1） | 宿主 close handler 同步执行：遍历所有组的脏文件序列化为 `pendingDirty[sessionId]`（上限 2MB；超限抛错阻止关闭）→ 允许关闭；下次打开同会话恢复为脏 tab + 横幅「已恢复 N 个未保存文件」 |
| 切会话/收起右栏 | body 保留，无数据风险 |
| 宿主 ⌘W | 同上（L1 close handler），不会静默丢内容 |
| 插件 dispose | 清 runtime 与快照；PTY/git 按现有 dispose 清理 |

### 4.10 快捷键与命令

- 保留 v1 的 8 条命令 id/键位，语义改为「打开/聚焦工作台 + 打开对应内部 tab」。
- 新增：`⌥⌘⇧W` 关闭当前内部 tab；`⌥⌘⇧B` 收起内部左栏；可选 `⌃Tab` 切 tab（先 `describeBinding` 查冲突，冲突则不做）。

## 6. 风险与限制

| # | 风险 | 影响 | 缓解 |
