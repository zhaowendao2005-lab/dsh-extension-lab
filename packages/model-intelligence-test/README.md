# 模型智能测试

普通指纹测试从 DSH 的真实模型目录选择模型；**a6api 专项指纹测试只能从官网油猴脚本提交选择进入**。两者共用官方 `lmfpd-sdk@0.2.0` 三题挑战、真实流式采样、指纹分析、测试记录和错误诊断。自定义 Agent 任务仍明确标注 Mock。

## a6api 专项：第一次连接

1. 更新本插件并打开 DSH 中任意会话，在右栏「模型智能测试」的功能中心点击「显示连接配置」，复制 JSON。
2. 在 Tampermonkey 新建脚本，用随包的 `integration/a6api-userscript.user.js` 完整替换内容并保存（版本 2.0.0）。关闭旧版脚本，避免两个版本同时运行；刷新 a6api 页面。
3. 在右上角浅色卡片的「连接设置」粘贴 JSON、保存，点击「连接 DSH」。配置包含本机 Host 地址和配对口令，不包含 API key。
4. 打开 a6api「令牌管理」：在新增的「测试令牌」列勾选专用测试令牌。选择按 **站点 origin + a6api 账号 ID** 保存到 localStorage，只保存 ID 与名称；账号切换后不共用。若行暂时禁选，使用站点的刷新列表/翻页，脚本会从站点已显示列表的响应中取得 ID，不读取 API Key 列或取密钥接口。
5. 到模型市场，在新增「测试渠道」列勾选目标。选择跨本页生命周期内的分页保留，刷新页面会清空渠道选择。卡片显示本页可选和累计已选数量。
6. 点击「送到 DSH 测试」，浏览器可询问是否打开 DSH。专项创建页收到清单后自动打开。此按钮只提交清单，不启动付费模型请求。

卡片默认右上角、可拖动标题栏、可收起，位置和收起状态保存在浏览器。独立 Shadow DOM 样式避免站点按钮文字颜色污染。表格勾选列使用真实 th/td；扫描时断开观察器，避免脚本更新引发循环。

## 专项创建与运行

专项页显示待测清单、测试令牌和 DSH 提供商目录。为每个启用的测试令牌**手动选择对应 DSH 提供商**，以用户选择为准；不自动核验 key 是否匹配，不复制或修改 DSH 提供商配置。映射按当前 Host profile、站点和 a6api 账号保存。

例如 20 个待测项、4 个测试令牌：

- 建立 4 个槽位，一个令牌对应一个槽位和一个选定的 DSH 提供商。
- 每槽领取一个待测项，通过油猴把该令牌固定到目标渠道（关闭智能兜底），读回确认成功后才采样。
- 使用该槽位的 DSH 提供商，通过 `llm.prepareCall` / 官方 `prepared.stream` **同时发送三条共享挑战**。
- 三条请求和流的清理全部结束，恢复本槽位原有固定关系，再立即领取下一项，不等其他槽位整批结束。
- 分析和结果保存继续复用现有指纹流程。专项最多 8 个槽位、64 个待测项；所有推理仍受运行时 18 条在途请求池约束。

专项页的快捷固定、加入路由、恢复只操作用户选中的测试令牌与一个明确目标。加入路由是独立的手动管理操作，不替代采样前的固定确认。运行中的令牌不接受手动改固定操作。

普通创建页没有 a6api 查询、API key 输入、JSON 导入或专项创建按钮。功能中心的「已从 a6api 收到的选择」可重新打开先前网页提交的清单，不创建新的网页选择。

## 深链接与双向通信

已核实当前 DSH 0.2.2-rc.3 的原生协议仅支持 **`dsh://open`**（以及尾斜线变体）：它只唤起安装版，不接受插件路径、selectionId、query 或 hash。

因此实现分两步：

1. 已配对网页先提交选择到当前 Host 的 `/mit-a6/bridge/selection`；
2. 网页调用 `dsh://open` 唤醒应用，插件常驻 Client 轮询 selection feed，并用官方 `sidebarRight.openTab` 打开专项页。

**安装版必须连接到同一个 Host/profile。** 独立开发 Host 不能靠原生链接切换安装版 Host。卡片提供「打开 DSH Web」备用入口，直接进入已配对的 Host；若没有当前会话，请先选一个 DSH 会话，再在功能中心打开已收到清单。

桥接复用 `webServer` 的现有本机监听端口，不启动额外服务。首次配对使用随机口令，后续会话绑定页面、站点和账号；网页接口只能提交选择、轮询指定站点操作和返回确认，不能执行任意 Remote 或启动推理。端点限制 loopback Host，不传 API key 或 cookie。Host 重启后需重新复制配对配置。

## 断线、取消与恢复

- 网页临时离线：后续槽位等待原账号页面重新连接，排队/固定等待不计入请求超时。
- 固定失败或未读回确认：不发送该项三题请求，保留可见错误。
- 取消：停止领取，向在途模型请求传递取消信号；在流清理和恢复确认之前不复用令牌。
- pin 前 Host 和油猴均保存补偿记录；重连/Host 重启后，仅同站点同账号可执行恢复。恢复时如果发现用户已外部修改固定关系，明确报错，不覆盖。
- 确定 pin 尚未写入的失败通过 `notApplied` 确认，不遗留永久恢复锁；写入结果不明则保留记录等待恢复。
- 恢复无法确认时本次任务停止，界面显示恢复失败；需检查网页补偿提示和实际固定配置，不能把它当作成功。
- 同一测试令牌跨任务共享身份锁；不读取真实 key 做重复检测。用户应为每个不同测试 key 配一个对应提供商。
- 不新增自动推理重试；保留现有“重试失败项”和“再次请求”。旧版直连 relay 记录缺少专项元数据，重跑明确要求从油猴重新创建专项。

## 指纹结论与指标

每次生成 3 条共享数字挑战，SDK 校验并分析。`scored` 只在 `reference_calibrated` 时显示参考库内闭集概率；`partial` 只显示 RAW 排序分数；`unscorable` 不评分；`not_model` 是行为检测结论，不是身份认定。最高候选不是模型真实身份概率，也不是智力排名。

响应经 DSH 官方 `AssistantStreamAccumulator` / `BlockAssembler` 组装；缺失 Token、TTFT 或生成时长显示 `—`，不估算费用。错误保留 Host 脱敏后的来源、code、HTTP status、原始信息与堆栈。只收到完整 block、没有 delta 时，不伪造首 Token 时间。

参考库由 SDK 下载并验证，缓存 `$DSH_HOME/cache/model-intelligence-test/lmfpd-data.bin`，无可用参考库时明确失败，不回退 Mock。请求超时 30–1800 秒，默认 180 秒；单回答最多 24,000 字符。普通并发可调，专项槽位由记录的令牌映射固定。

## 构建与验证

在本包目录运行 `pnpm build`，包含 TypeScript、静态分层约束、Host/Client 打包和 scoped CSS；`lib/` 均由构建生成。`test/a6-orchestration.test.mjs` 是经本次实施计划授权的本地调度/桥接检查，使用可控流，不访问真实模型或修改 a6api 配置。

UI 检查与真实采样分别报告：构建与本地检查成功不代表 Tampermonkey 安装、GM 权限、原生唤起确认或真实供应商账单链路已实测。更新插件和油猴后才会使用新代码；没有安装就不声称正在运行的 DSH 已更新。
