# 模型智能程度测试

右栏入口：**模型智能测试**。指纹测试已接入真实 DSH 模型调用与官方 [lm-detector](https://github.com/Ikaleio/lm-detector) / `lmfpd-sdk@0.2.0`。自定义任务仍为独立 Mock 演示，不伪装为真实 Agent 执行。

## 指纹流程

1. 从插件当前所在 DSH runtime 的真实模型目录选择供应商/模型。
2. 每条测试生成一组 **3 个共享挑战**；每题要求凭直觉输出 292–332 个 1–355 整数。所有所选模型使用同一组题目；每模型发送 3 次真实请求，可能产生供应商费用。
3. Host 使用 DSH 官方 `createUserMessage` 创建消息，经 `llm.prepareCall` → `prepared.stream` 发送；响应由官方 `AssistantStreamAccumulator` 记录、`BlockAssembler` 组装正文、usage 和 finish，兼容 delta 与完整 `block-end`，不自行拼接流。沿用当前适配器默认参数，不附加交付约束、工具或 Agent 对话历史，不另写自动重试；不经过 SDK 的 API-key 请求功能，也不把供应商凭据传到浏览器。运行时缺少官方准备接口则明确报不兼容，不回退到自制请求。
4. SDK 解析、校验并分析回答，显示真实候选排名、样本诊断和参考库版本。

- `scored`：完整有效样本的排名；仅 `reference_calibrated` 才展示库内校准概率。
- `partial`：只有部分有效样本，展示原始排序分数，不造出置信概率。
- `unscorable`：有效样本不足，不能评分。
- `not_model`：数列特征未通过 SDK 检查，不展示排名；这是行为检测结论，不是身份认定。

最高候选代表**参考库中最相似的行为模式**，不是“真实模型身份概率”，更不是智力排名。库外模型仍可能匹配库内某个候选；低置信或异常样本需谨慎解释。

## 参考库与运行边界

使用官方默认数据源 `https://lm.ikale.io/data/` 和 `https://cdn.jsdmirror.com/npm/lmfpd-data@latest/`。SDK 负责库/检测器配对校验、下载和磁盘缓存，缓存位置为 `$DSH_HOME/cache/model-intelligence-test/lmfpd-data.bin`。缓存检查 TTL 为 1 小时，Host 每 10 分钟重新取得检测器快照；过期缓存由 SDK 后台刷新，新测试随后采用新版，已有任务固定原版本。更新失败继续用可验证的旧缓存；无可用缓存则明确报错，**不回退 Mock**。SDK 不兼容的新数据格式需要升级依赖，不自动执行代码更新。

- 单任务最多 64 个模型；模型并发槽位 1–6（默认 6），每个模型的三条挑战始终同时发出，因此默认 6 槽即 18 路并发请求。整个插件最多 18 个同时进行的采样请求、4 个进行中的测试；全局池按模型整批预留本次待发样本的容量，不拆开三题。超出槽位或全局池的模型显示为排队，排队不计入请求超时或 TTFT。
- 模型并发与单请求最大时长（30–1800 秒，默认 180 秒）可在记录的「配置」面板中实时调整：降低并发或时长不会打断已开始的请求（新值只影响之后发起的请求），提高时长会延长进行中的请求。
- 回答最多保留 24,000 字符，超限标为截断。无有效回答不编造候选。
- 失败样本可在表格「操作」列按模型重试：只重发该模型的失败样本，保留其已完成样本并重新分析；已取消的测试不能重试。
- 采样失败时「采样信息」会附带 Host 侧脱敏后的诊断：错误来源、`code`、HTTP `status`、供应商原始信息与堆栈，展开即可查看，用于区分认证失败、限流、模型不存在或适配器异常；密钥类文本在离开 Host 前已被替换为 `[redacted]`。
- 完成任务保留最多 1 小时，并在新任务创建时按总记录上限 16 清理；不是持久化任务服务。
- 关闭内部页签不会取消；显式取消会中止未结束的请求。删除/清空/卸载会尝试取消任务。浏览器强制关闭、进程崩溃或断网不能保证送达取消命令，Host 超时仍生效；刷新后不恢复内存记录。
- 轮询暂时失败只显示连接错误，不能据此宣称后台执行失败。

## 指标

真实输入/输出 Token 使用 Host 的 `usage`，缺失显示 `—`；指纹费用未接入定价，不生成模拟费用。TTFT 使用 DSH 官方首 Token 判定，是请求开始（含准备阶段）至首个非空文本/推理 delta 或工具调用 delta（不是网络首字节）；生成时长从首个到最后一个符合判定的 delta，端到端时长含等待及收尾。仅收到完整 block 而没有 delta 时仍能获取回答，但 TTFT/生成时长留空，不以 block 到达时间伪造。跨样本按相同有数据样本累加分子与分母，排除队列和分析。单个分块无法测得生成时长时不造速率。

## 测试记录与请求

测试记录与请求（attempt）由 Host 持久化在 DSH 存储域 `model_intelligence_test`（开发沙箱里就是沙箱 runtime 的数据目录），全局共享，不再按会话隔离；所有会话的面板共用同一个工作台。一条记录固定所选模型/渠道和配置；「再次请求」在同一记录内追加 #2、#3…，每次重新生成 3 道题，模型不可增减；上一请求未结束时新请求排队，结束后自动开始。结果、汇总、重试失败项都只针对当前选中的请求。运行时重启后未完成的请求标记为「已中断」。

## 中转站来源适配

`+` 页签右侧的「功能中心」→「中转站来源适配」是独立功能页，不是测试记录。左侧为适配站点（当前仅 a6api），顶部逐行为提供商、模型（模糊搜索多选，fzf 式子序列打分 + 别名）、保真（全部/保真/直连）和排序，主表按渠道挂载展示公开模型目录。数据来自中转站匿名只读接口，经 Host 代理并缓存整份快照（TTL 10 分钟，可手动刷新，快照落盘到 `model_intelligence_relay`）；浏览器不直连第三方站点，也不接触第三方密钥。

- 列：收藏、模型（含厂商）、渠道（含描述）、价格（含实时倍率）、成功率、24h、首字延迟、吞吐、缓存命中、路由标签、保真、最近采样、状态等；列可勾选、宽度可拖动。
- 右侧抽屉（不遮挡表格，毛玻璃滑入）按需读取 24 小时/7 天成功率桶、实时并发和 SVG 检测（需登录令牌），可收藏或加入分区。
- 收藏是默认分区；可新建分区并把渠道加入（购物车概念），在创建测试的模型选择器左栏按「DSH 模型 / 中转分区」挑选。中转渠道采样以 `sk-<API Key>-<channel_id>` 直接调用中转站（chat/responses/messages 三种格式，可按条目指定）。

## 设置「API 适配站点」

DSH 设置里新增「API 适配站点」页：API Key、系统访问令牌 + 用户 ID 都存进 DSH 凭据服务（`MIT_A6API_*`），前端只看到是否已配置；令牌可校验。有 API Key 才能测试中转渠道。

「加入模型池」后，模型经**插件自带的 LLM 适配器**注册成普通提供商路由（`a6api-chat-<hash4>` / `a6api-responses-<hash4>` / `a6api-messages-<hash4>`），DSH 自己的请求管线（历史、系统提示、工具、重试、超时、计量、压缩）全部照旧，适配器只负责把归一化请求映射到 `chat` / `responses` / `messages` 三种上游协议并还原成流式 chunk。注册表变化后即时 `registerAdapter` / `handle.replace`，无需重启；关闭功能或一键清理会撤掉路由。

为什么不复用 DSH 现成的 pi-ai 适配器：`@deepseek-ai/dsh-llm-pi-ai` 只导出 `PiAiAdapter` 类，而构造它需要的 `profiles` / `resolveApiKey` / `authContext` 生产者（`resolveProfiles`、`createModels`、`authContextFrom`、`providerDefaultsOf`）都是内部实现；再挂一个 pi-ai 实例又会因 `apply()` 无条件声明全部目录提供商而撞上 `DUPLICATE_DIRECTORY`。所以只写协议映射这一层，路由 id 全部带哈希前缀，与 pi-ai 的提供商互不重叠，重复注册会以 `DUPLICATE_ADAPTER` 明确失败而不是静默覆盖。

模型能力（图片输入、思考等级）按模型名推断（`backend/relay/traits.js`），注册进路由后仍可在设置里改：`inputModalities` 目前固定为 `["text"]`（图片会自动被运行时降级成文本投影），思考等级映射为 `reasoning_effort`（chat）/ `reasoning.effort`（responses）/ `thinking.budget_tokens`（messages）。
- 每条记录是 `listing_id + channel_id + supplier_id` 的复合身份；同一 listing 在不同渠道下不会被误合并。快照加载按该身份去重，筛选/排序在 Host 完成，前端按固定行高虚拟滚动。
- 当前只做匿名只读：固定商家、加入路由、模型检测需要登录，界面显示为不可用并提示能力边界；不伪造登录态，也不写第三方数据。
- 首次进入会逐页读取约 1–2 万条渠道（500 条/页，4 路并发）；快照就绪后筛选即时生效。站点接口失败显示固定错误，不回退 Mock，不把供应商原文直接展示。

## 界面与其他数据

- 全宽可关闭页签、记录侧栏；进度视图显示全部运行，结果视图显示已结束运行。模型详情替换内容区页面，以面包屑返回。
- 分组多选、完整方形标签、文字/拼音/首字母搜索；毛玻璃菜单支持外部点击和 Escape 关闭。
- 可选表格列、键盘/拖动列宽、固定右侧结果和操作列。
- 自定义任务的轮次、指标、费用和 HTML/SVG 成果仍明确标注 Mock，不启动服务或 Agent 沙箱。只有内置样例在受限 iframe 中执行绘图脚本。
- 预设按浏览器 origin 保存，不是账号同步；陈旧写入会报错但 localStorage 无跨窗口原子锁。记录、请求、分区和中转快照在 Host 持久化；草稿、页签和表格状态在内存中，所有会话共享。
- 中文优先 UI；管理器元数据提供中英文。

## 构建与接入

Node.js >=22.19.0，pnpm 12.15.0。在包目录运行 `pnpm install`、`pnpm build`。构建包含 TypeScript、静态架构约束、Host/Client/scoped Tailwind CSS 和 sourcemap；`lib/` 为生成产物，禁止手改。React 由 DSH ModuleLoader 提供。依赖生命周期审批不自动放行。

Host 公开 32 个 owner-only Remote 方法（`catalog`、`records*`/`record*`、`attempt*`、`customSave`、`partition*`、`relayAuth*`、`relayProvider*`、`relay*` 数据读取（含 `relayResolve` 渠道存活查询、`relayRetryMissing` 补抓失败页）、`tags*` 标签，清单见 `shared/contract.js`），Client 经 Typert Remote 调用。在开发沙箱内读写的是沙箱 runtime 的模型、存储和凭据；只有用户在设置页主动「加入提供商」时才改 pi-ai 配置。

架构见 `ARCHITECTURE.md`，本包规则见 `AGENTS.md`。没有修改仓库根构建脚本或市场索引。浏览器验证只能在用户授权范围内执行。

## 收藏页、标签与价格单位

- **收藏页**：「中转站来源适配」顶部切到「收藏」，列出收藏渠道（a6api 带价格，可切美元 / 人民币，汇率取上游实时汇率）。「加入模型池」选协议后写入设置「API 适配站点 → 插件管理的提供商」。
- **标签**：收藏页与测试结果详情页都能给渠道 / 模型打标签；分类为「接近：<模型>」（指纹概率分布中的候选，按模型分配颜色）、「不降智 / 降智」、「带真实测试」。标签是 Host 全局文档（`tagsList` / `tagsSet`），目标键 `relay:<站点>:<渠道>:<模型>` 或 `model:<提供商>/<模型>`。
- **已过期**：除渠道列表页外，凡展示渠道的位置（收藏页、模型选择器、测试结果）在快照里找不到该渠道时显示「已过期」和「清除」。快照尚未能回答时显示「查询中」，不会误判过期。
- **快照读取**：并发 6 页、不重试；任何 429 / 其他错误原样展示，并保留已读到的渠道，可点「补抓失败页」。
