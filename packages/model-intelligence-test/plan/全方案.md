# 模型智能测试 · 全方案

> 状态：方案定稿中，尚未实现。各阶段完成后只保证编译通过，Playwright 验证由用户执行。
> 标注「待验证」的接口尚未实际调用过，见第九节。

## 一、目标与范围

最终打通的链路：

**中转站挑渠道 → 收藏到分区 → 指纹测试（可多次请求）→ 加入 DSH 提供商 → 日常聊天使用**

| 范围内 | 范围外（本版不做） |
|---|---|
| a6api 一个站点（结构上预留新站点） | a6api 站内写操作：禁用渠道、固定商家、加入路由 |
| 公开渠道数据 + 系统访问令牌才能看的数据（检测徽章、SVG 检测） | 账号密码登录、GitHub / Google 登录 |
| 收藏 / 分区本地存储 | 同步到 a6api 站内收藏 |
| 指纹测试真实调用；自定义测试仍为模拟 | 调用合规（频率限制、总量上限），后续再做 |
| 每个阶段保证编译通过 | 自动化测试；Playwright 由用户执行 |

## 二、整体分工

```
浏览器界面（Client）   只负责显示和操作，不接触任何凭据
      │ 插件远程方法（只允许本机所有者调用）
插件后台（Host，Node 进程）
  ├─ a6api 请求：Node fetch；需登录接口带 Authorization: <令牌> + New-Api-User: <用户ID>
  ├─ 指纹测试：DSH 模型走 llm.stream；中转站渠道用 "API Key-渠道ID" 直接请求
  ├─ 持久化：DSH storageDomain（开发时位于沙箱目录）
  ├─ 凭据：DSH credentials（API Key、系统访问令牌、用户 ID）
  └─ 加入提供商：DSH settings 服务写入 pi-ai 配置（方案 B）
```

- DSH 不是无头浏览器。Host 是 Node 进程，请求就是普通 HTTP。
- DSH 自带的右侧栏 Browser 只给用户看网页，插件读不到其内容 / cookie。仅用于「在浏览器中打开 a6api（获取令牌）」按钮。
- 指定渠道调用：`sk-xxx-<channel_id>`，注意是 `channel_id` 不是 `listing_id`。

## 三、数据与持久化

### 3.1 全局化

工作台、测试记录、分区、站点快照全部改为 **DSH 全局一份**，不再按会话区分。换会话看到同一份数据，打开的标签页也一起保留。

### 3.2 存储表（storageDomain，带版本号）

| 表 | 内容 |
|---|---|
| `records` | 测试记录：名称、类型、创建时间、模型集合（DSH 模型 / 中转站渠道）、配置 |
| `attempts` | 一条记录下的每一次请求（见第四节）：序号、发起时间、挑战题、各模型 3 次采样、分析结论、状态 |
| `partitions` | 分区。「收藏」为默认分区、不可删除；其他分区用户自建 |
| `partitionItems` | 分区内的渠道：站点、`channel_id`、模型、加入时间、标签、备注、加入时的快照（价格 / 成功率） |
| `relaySnapshots` | 站点快照缓存：列表全量快照 + 时间戳，TTL 10 分钟，过期后后台刷新、失败继续用旧的 |
| `managedProviders` | 插件写入 pi-ai 的提供商清单（用于禁用样式标注与清理） |
| `workbench` | 打开的标签页、当前标签、侧栏折叠、列配置 / 列宽 |

- 运行中的请求不跨重启续跑：DSH 重启时把未结束的采样标为「已中断」，保留已完成的部分，可对该次请求「重试失败项」。
- 凭据不进 storage，只进 credentials。

## 四、指纹测试：请求记录机制（补充需求）

### 4.1 概念

- **测试记录（record）**：一次测试的定义 = 选中的若干模型 / 渠道 + 配置。
- **请求（attempt）**：对这条记录的一次完整执行。每个模型 3 道挑战题、3 次采样，产出一次分析结论。
- 一条记录完成一次请求后，可以 **「再次请求」**，在 **同一条记录里新增一个请求**（第 2 次、第 3 次……），而不是新建记录。

```
测试记录「DS41 渠道对比」
 ├─ 请求 #1   11-12 14:35   2 模型   已完成
 ├─ 请求 #2   11-12 16:02   2 模型   已完成
 └─ 请求 #3   11-12 18:40   2 模型   运行中
```

### 4.2 行为

- 「再次请求」按钮位于记录页工具栏；上一次请求运行中时不可点（或排队，待确认）。
- 每次请求 **重新生成 3 道挑战题**（遵循 lm-detector 官方随机化：随机长度 292–332、随机语言）。
- 默认沿用记录的模型集合；是否允许本次增减模型见第十节问题。
- 并发、超时等配置沿用记录配置，可在发起前修改；修改仅作用于本次及以后的请求。
- 「重试失败项」作用于某一次请求内部，不新增请求。

### 4.3 展示

- 记录页顶部新增 **请求切换条**：`#1 · #2 · #3（运行中）`，默认显示最新一次；切换后表格 / 详情显示对应请求。
- 新增 **「汇总」视图**：按模型一行，横向展示每次请求的最高匹配候选与概率，便于看结论是否稳定：

| 模型 | #1 | #2 | #3 | 一致性 |
|---|---|---|---|---|
| deepseek/deepseek-v4.1-flash | v4.1-flash-1017 94.5% | v4.1-flash-1017 88.1% | … | 2/2 一致 |

- 详情页面包屑：`测试记录 / 记录名 / 请求 #2 / provider/model`。
- 左侧记录栏每条记录显示请求次数与最近一次状态。

### 4.4 后端

- engine 的 job 与 attempt 一一对应；`fingerprintStart` 增加 `recordId`，返回 `attemptId`。
- 结论在请求结束时写入 `attempts` 表；运行中状态仍走 status 轮询。

## 五、中转站来源适配（列表增强）

### 5.1 快照

- 列表：全量快照每页 500 条（轻量，64 字段，不含 b24/b7d）。
- 详情：抽屉里点按钮，按 `channel_id + model` 以小页（≤100）补拉 24h / 7d 数据（`b24` 24 个小时桶、`b7d` 7 个天桶）。
- 并发：可见行 / 抽屉调用匿名接口 `channel-concurrency/query`。

### 5.2 筛选栏

- 第一行 **提供商**、第二行 **模型**：模糊搜索多选菜单。
  - 选中项横向排列、按宽度自动换行；点选时菜单不关闭；点外部或 Esc 关闭。
  - 模型选项受已选提供商约束。
- 第三行 **排序**：综合推荐 / 价格升 / 价格降 / 成功率优先 / 延迟优先。
- 第四行 **保真**：全部 / 保真（金银铜徽章）。「直连」匿名拿不到字段，令牌可用后再评估。
- 搜索算法：fzf FuzzyMatchV2 思路（有序子序列 + 词边界加分），参数：
  - 匹配 16、空白边界 10、分隔符边界 9、普通边界 8、驼峰 / 数字 7、连续 4、首字符 ×2、开始缺口 -3、延续缺口 -1；
  - 按 `len(q)*(16+10)` 归一，叠加长度惩罚与紧凑度；
  - 无序回退 ×0.42；
  - 叠加拼音 / 首字母匹配与别名表（如 `ds → deepseek`）。
  - 同一套算法用于指纹测试的模型选择器。

### 5.3 表格（对齐官网截图）

| 列 | 内容 |
|---|---|
| 收藏 | ☆ 按钮；当前分区高亮；点击即加入 / 移出当前分区 |
| 模型 | 厂商图标 + `model_name` |
| 渠道 | `渠道 #channel_id` + `description`（商家描述） |
| 价格 | 输入 / 输出价、实时倍率、官方价对比（低于官价标注）、价格变动时间 |
| 成功率 | 实时色块条（`success_buckets`），绿 ≥95 / 黄 ≥90 / 橙 ≥80 / 红；24h、7d 在抽屉中按需加载 |
| 首字 / 吞吐 | `p50_ttft_ms`、`throughput_tps` |
| 缓存率 | `cache_hit_rate_24h` 进度条 |
| 标签 | 稳定(绿)、低价(蓝)、高速(橙)、高质(橙)；保真金 / 银 / 铜徽章 |
| 最近采样 | `last_sample_at` 相对时间 |
| 检测 | 检测徽章 / SVG 检测（需令牌，点击才加载） |
| 操作 | 加入分区、去指纹测试、详情 |

- 保留：列选择、列宽拖拽、虚拟滚动（44px 行高、overscan）、行唯一键 `listing_id:channel_id:supplier_id`。

### 5.4 详情抽屉

- 从右侧滑入，带动画与毛玻璃；浮在表格上方，不挤压表格；Esc / 点外部关闭。
- 内容：基本信息、价格对比、实时色块、「加载 24h」「加载 7d」按钮（悬停显示每段请求数、成功率、延迟、首字、缓存率）、最近失败时间与错误码、最近成功时间、当前并发 / 上限、SVG 检测（需令牌，点击加载并渲染 svg）。
- 底部动作：加入分区、去指纹测试、加入提供商。

### 5.5 视觉

- 瑞士国际风格，主色淡绿，少圆角，用不同粗细分隔线做装饰；标签与徽章用官网配色区分。
- 标签页关闭按钮增加悬停态。

## 六、收藏 / 分区（购物车）

- 收藏与购物车合并为「分区」：收藏 = 默认分区；用户可新建、重命名、删除自建分区。
- 在中转站页先选「当前分区」，表格里点 ☆ 即加入 / 移出。
- 分区内渠道可打标签、写备注；显示加入时价格 / 成功率与当前值对比。
- 分区是指纹测试与加入提供商的来源。

## 七、设置页「API 适配站点」

- 通过 `settings.section` 插槽新增一页（只加这一页）。
- 列表展示 a6api，另有「新增中转站」入口（预留，暂不可用）。
- a6api 配置项：
  - API Key（调用模型用）；
  - 系统访问令牌 + 用户 ID（查看登录后数据用），附「在浏览器中打开 a6api」按钮方便获取；
  - 状态：已配置 / 用户名 / 校验结果；不回显凭据；失效时提示重新填写。
- 页内还展示收藏 / 分区列表，支持与中转站页相同的提供商 → 模型筛选与排序，可选中渠道「加入模型」并选择 API 类型。
- 中转站页的「配置」按钮跳转到这一页（直达分区接口待验证；不行则打开设置并高亮该项）。
- 未配置 API Key：只能浏览、收藏、分区；「去测试」「加入提供商」置灰并提示去配置。

## 八、闭环

### 8.1 指纹测试模型选择器

- 弹层左侧新增来源栏：
  1. DSH 可用模型（现有）；
  2. 中转站分区树（站点 → 分区 → 渠道）。
- 两个来源的选中项合并为同一个已选列表，标签上注明来源。
- 中转站渠道调用：Host 用 API Key 拼 `-channel_id`，按渠道 `test_endpoint` / 选定 API 类型发请求。

### 8.2 加入提供商（方案 B）

- 通过 DSH `settings` 服务写入 pi-ai 配置：
  - 每种 API 格式一个提供商：openai-completions / openai-responses / anthropic-messages；
  - 名称 `a6api-<格式>-<4位哈希>`，避免与用户已有提供商重名；
  - Key 写入凭据服务，配置只引用 `apiKeyEnv`；
  - 模型 id 来自分区里选中的渠道。
- 设置 → 模型页中，插件写入的提供商以 **禁用样式** 展示并标注「由「模型智能测试」插件管理」：用户可查看，不可编辑 / 删除；修改只能回插件页面。
- 插件关闭时自动移除；被强制关闭 / 卸载可能残留，插件页提供「一键清理」。

## 十、待验证与待确认

**待验证（实现前先查实）**

**已确认（用户 11-12 22:15）**

1. 「再次请求」不能增减模型，固定沿用记录的模型集合。
2. 上一次请求运行中时，「再次请求」允许排队：新请求进入「排队中」，前一次结束后自动开始。
3. 汇总针对单次请求，不针对测试记录：「测试结果」视图展示当前所选请求的汇总；不做跨请求一致性列（4.3 中的跨请求汇总表作废）。
