# 自定义测试模块需求

状态：初稿（仅设计，不代表当前已实现能力）

## 1. 背景与目标

插件已有两条成熟测试路径：

- 普通指纹测试：沿用 DSH 真实模型目录、统一挑战、流式采样和结果记录。
- a6api 专项指纹测试：油猴脚本从 a6api 网页发送待测渠道清单，Host 使用账户凭据执行测试。

自定义测试是现有指纹测试体验的扩展：保留相同的模型选择、任务创建、监控列表和结果记录风格，但执行内容从固定的三条指纹挑战扩展为完整的 DSH 会话任务。每个模型拥有独立运行单元、沙箱和输出文件。

目标：

1. 从现有自定义测试创建页选择普通 DSH 模型并创建任务。
2. a6api 只提供两个入口：指纹测试结果页发起，或油猴脚本直接创建/发送 a6api 自定义测试选择；不新增插件端 a6api 渠道搜索入口。
3. 每个模型拥有独立、可追踪、默认拒绝外部访问的沙箱目录。
4. 在测试操作页的配置菜单中设置并发数，查看任务实时进度和模型会话详情。
5. 模型输出由预设和会话规则约束，结果列表可打开已验证的输出文件。
6. 提供默认预设“龙猫测试”，验证 HTML + Canvas 动态绘图任务链路；HTML 限制只适用于该预设，不作为所有自定义测试的通用输出限制。

## 2. 当前实现与设计目标

当前自定义任务中的 Mock 适配器和 Mock 预览只是过渡实现，必须替换为真实 Host 执行适配器和真实文件结果链路；不能把 Mock 结果标为模型成果，也不能把 Mock 当作最终验收。

普通模型和 a6api 模型共享同一个任务、运行、监控和账本模型。差异只存在于 Host 执行适配器：普通模型复用 DSH 会话/模型调用能力，a6api 复用现有网页选择、固定、测试 Key、流传输和账本能力。平台能力和阶段安排见 [架构草案](./architecture.md)。

## 3. 用户故事

### 3.1 普通模型

用户沿用现有指纹测试的模型目录和选择风格，选择一个或多个普通 DSH 模型、预设和运行参数，创建自定义测试。每个模型独立执行；一个模型失败不覆盖其他模型状态。

### 3.2 a6api 模型

用户可以在指纹测试结果页对已有 a6api 结果发起自定义测试，也可以在油猴脚本中直接选择 a6api 渠道/模型并发送到自定义测试。油猴仍然只是一次性发令器；Host 接收选择后独立执行，不要求网页保持打开。

DSH 插件内不新增 a6api 市场搜索、API Key 输入或第二套 a6api 创建入口。a6api 选择数据只包含渠道/模型身份、市场快照和测试令牌选择所需的非机密信息。

### 3.3 监控与结果

监控列表沿用指纹测试结果页的紧凑表格和状态表达。点击模型行打开该模型的独立会话详情；点击已验证的输出文件打开预览或交给 DSH 现有的文件/VS Code 打开能力。阶段不仅表示单次请求，还要覆盖完整 DSH 会话生命周期：排队、准备、会话运行、工具/文件操作、验证、完成或失败。

### 3.4 会话权限

会话详情展示当前 run 被允许访问的沙箱根目录、输入/输出文件和工具能力。默认只允许当前沙箱，不允许工作区、网络、宿主凭据、其他模型目录或操作 Key。

## 4. 入口设计

### 4.1 普通自定义测试入口

直接改造现有自定义测试 Mock 创建页，保留现有 DSH 插件的创建风格和布局。它提供普通模型选择、预设选择和运行配置，不另造一套页面。

### 4.2 a6api 入口

a6api 只有两个入口：

- **指纹测试结果页**：对已有 a6api 模型/渠道结果执行“创建自定义测试”，带入身份和必要市场快照。
- **油猴脚本**：在 a6api 网页选择渠道、模型和测试令牌后，直接发送一次自定义测试选择到 Host；它可以创建任务或把选择送入现有创建流程，但不参与执行、不回传、不轮询。

这两个入口最终都进入同一个 Host 创建命令和同一个任务数据模型。插件端不提供 a6api 渠道搜索或 API Key 配置。

### 4.3 结果与身份

普通模型结果带入 DSH provider/model 身份；a6api 结果带入 channel/model 身份和必要市场快照。只带入身份和快照，不复制原始响应、密钥或历史 prompt。用户可以在统一创建页继续添加其他模型。

## 5. 创建向导

创建页沿用指纹测试的选择和快照确认风格，分为四步：

1. **选择目标**：普通 DSH 模型或由结果页/油猴导入的 a6api 渠道模型；显示 provider、model、来源和重复项提示。
2. **选择预设**：选择已有预设，或编辑一个以 prompt 为核心的预设内容。预设本身不写死具体输出文件；输出声明由会话规则和 Host 验证生成。
3. **运行参数**：在测试操作页的配置菜单中设置并发数、单模型超时、失败策略和是否继续其他模型。Host 校验最终有效值。
4. **输出配置**：默认只配置输出声明和文件名约束，不把 HTML 设为所有自定义测试的通用限制。`龙猫测试`预设要求 HTML 输出；其他预设的输出格式由已确认的 Host 能力和预设契约决定。

创建前显示最终快照：目标列表、prompt、规则/预设版本、配置版本、并发设置和输出声明。任务启动后这些字段不可静默改变。

## 6. 默认预设：龙猫测试

预设名称：`龙猫测试`。

任务意图：让模型创建一个使用 HTML + Canvas 的动态龙猫壁纸，并把结果写成当前模型沙箱内的 HTML 文件。

要求模型按顺序完成：

1. 在沙箱内创建 `totoro.html`。
2. 使用 Canvas 绘制主体、背景、动画循环和必要的交互/降级逻辑。
3. 检查文件可以作为独立 HTML 输出。
4. 通过受限输出声明能力登记相对路径，例如 `output/totoro.html`。
5. 在会话结果中报告文件路径、大小、最后修改时间和验证状态。

该预设不要求网络、下载素材或读取工作区文件。无法完成时标记失败/部分完成，不得用内置图片或 Mock 内容冒充模型生成。

## 7. 沙箱模板

每个模型运行单元创建独立目录：

```text
<custom-test-root>/<task-id>/<model-run-id>/
├── RULES.md
├── config.json
├── input/                 # 可选，初始输入只读快照
├── output/                # 经声明和校验的结果文件
└── session/               # 会话日志与状态，不暴露凭据
```

`RULES.md` 说明任务目标、预设允许的输出、只能读写当前沙箱，以及不得访问网络、工作区、其他模型目录、DSH 配置或凭据。输出声明只能通过受限能力更新，不能获得任意配置写权限。

配置初版允许未声明输出：

```json
{
  "version": 1,
  "output": {
    "format": "html",
    "file": null
  }
}
```

`format: html` 和 `output/totoro.html` 是“龙猫测试”预设的约束，不是所有预设的全局约束。Host 必须拒绝绝对路径、`..` 穿越、符号链接逃逸、未知格式和沙箱外文件。

## 8. 监控面板与详情 Tab

任务级视图显示：任务状态、目标数量、完成/运行/失败数量、并发上限、开始时间、已用时间和整体错误。

模型行显示：

- 模型/渠道名称和来源。
- 当前阶段：queued、preparing、running、tooling、validating、completed、failed、cancelled、interrupted。
- 当前会话 ID、沙箱状态、步骤/事件计数；没有可靠百分比时不伪造百分比。
- 输出文件：未生成、生成中、可打开、校验失败。
- 输入/输出 Token、请求数、费用和缓存率；未知值显示“未知”，不以零代替。
- 最后错误和显式重试入口。

点击模型行打开独立详情栏，沿用 DSH 极简会话风格，但使用 Tab 拆分内容，避免单次请求详情堆在一页：

- **Chat**：消息、工具调用摘要、会话状态和时间线。
- **文件**：沙箱目录树、输出声明、文件事件、大小/修改时间和打开入口。
- **指标**：请求列表、每次请求的首字可观测延迟（TTFT）、模型输出时长、输出 Token、模型吞吐量和端到端速度。
- **账单**：每次请求的请求 ID、输入/输出 Token、缓存读写 Token、费用、结算状态和歧义原因。
- **权限**：当前会话允许和禁止的能力、沙箱根目录和资源范围。

指标页使用 ECharts 折线图展示请求序列中的速度和缓存率变化；图表必须标明单位、数据来源、缺失/歧义状态和时间范围。定义如下：

- 模型吞吐量 = 输出 Token / 模型输出生成时长。
- 端到端速度 = 输出 Token / 单次请求总耗时；总耗时从请求发出到请求完成，包含排队/首字前等待时必须明确标注。
- 首字延迟（TTFT）= 请求发出到首个可观测输出增量的时间。
- 缓存率优先使用有明确状态的站点缓存字段；缺失、未结算或来源不一致时显示未知。

详情栏关闭不取消任务；取消、重试和删除必须是显式操作。

## 9. 并发和失败策略

- 并发颗粒度是同时执行的模型数，不是单个模型内部的消息或工具事件数。
- 用户在测试操作页的配置菜单中设置任务并发数；Host 最终受全局请求池、供应商/a6api 限流和单模型约束裁剪，降低并发不抢占已开始的 run。
- a6api 还受“已分配的测试令牌数”约束：有效并发 = `min(用户设置并发数, 可用测试令牌数, Host 全局容量)`。每个测试令牌同一时刻只服务一个模型 run。
- 同一模型不得被两个运行单元同时写入同一沙箱；一个模型失败不自动取消其他模型。
- 取消先停止领取新模型，再中止在途会话；清理完成前不复用资源。
- 默认不自动重试模型推理。显式重试创建新的 run/execution，保留原始失败记录。
- a6api 固定、取 key、路由和解固定继续由 Host 执行；固定未确认时不发送数据面请求。

## 10. 结果与打开文件

只有 Host 完成路径校验、文件存在性和预设格式验证后，结果行才显示“打开输出”。打开动作使用 DSH 已授权的文件/文档预览能力；允许调用 DSH 现有的 VS Code/工作区打开实现，但不能把未经授权的任意本地路径直接交给浏览器。

HTML 预览使用无同源权限的隔离 iframe，允许龙猫 Canvas 动画所需的本地脚本；网络请求、顶层导航、父页面访问和外部资源加载必须被阻断。其他格式按预设和 Host 能力决定是否支持。

不支持预览时显示文件元数据，并提供宿主允许的下载或“在应用中打开”能力；不把完整文件内容复制到 Client 状态。

## 11. 数据与隐私要求

- Client 只保存任务摘要、稳定 ID和展示状态；完整会话、文件和执行事实由 Host 保存。
- 普通模型不向 Client 传凭据。
- a6api 不向 Client 或沙箱传账户访问令牌、测试 key 或操作 key 明文。
- 日志脱敏，不写 prompt 中的密钥、完整 Authorization、cookie 或外部路径。
- 删除任务前检查在途会话和持久租约；删除不能产生晚到写入。
- 任务结束后默认保留结果和日志，沙箱清理由显式“删除任务/清理成果”触发。

## 12. 非目标

首版不包含：

- 任意代码执行、通用终端或未授权工具。
- 网络访问、外部工作区访问、跨模型共享目录。
- 未经预设契约允许的多文件输出、图片/视频/压缩包输出。
- 自动修改 DSH provider 配置。
- 自动把自定义任务结果纳入指纹评分或模型排名。
- 用 Mock 预览或 Mock 适配器冒充真实模型输出；现有 Mock 只能作为过渡开发替身，正式实现必须替换。

## 13. 验收标准

1. 普通模型和 a6api 模型从各自允许的入口进入同一个创建流程、任务模型和监控视图。
2. 创建页保留指纹测试的选择、快照和结果风格；a6api 不新增插件端市场搜索入口。
3. 普通模型与 a6api 模型在 Host 侧有清晰的真实执行适配器，凭据不进入 Client。
4. 并发按模型计数；a6api 同时受用户并发设置、测试令牌数和 Host 全局容量约束。
5. 每个模型的沙箱路径独立且不能穿越；默认无网络和无工作区访问。
6. “龙猫测试”能生成并验证当前模型沙箱内的 `output/totoro.html`，失败时状态准确。
7. 监控行、Chat/文件/指标/账单/权限详情 Tab 和输出文件入口可以从同一个任务稳定恢复。
8. 请求级 TTFT、输出时长、模型吞吐量、端到端速度、缓存率和账单状态有明确来源和单位；未知数据不填零。
9. 旧指纹记录、a6api 自动采样和全局操作 Key 功能不受影响。

实施顺序及平台待确认项统一维护在 [架构草案](./architecture.md)，本文件仅保留需求与验收标准。
