# 重构方案：从「中转站爬取面板」到「官方口径 + key 槽」

> 本文是实施依据。调研证据见 `plan/research/a6api-pin.md`、`plan/research/a6api-market.md`。

## 1. 目标与边界

**删除**（用户已确认）：
- 中转站快照/爬取链路：`backend/relay/snapshot.js`、`site.js`、`traits.js`、`client.js`
- 渠道表格与详情、收藏、分区：`frontend/views/relay/*`、`stores/relay*`、`service/relay.service.ts`
- 渠道/模型标签：`backend` 的 `tags*`、`frontend/views/tags/TagEditor.tsx`、`components/tags.ts`
- 插件自带的 pi-ai 提供商路由：`backend/relay/adapter.js`、`providers.js`、`components/price.ts`
- DSH 设置页「API 适配站点」：`frontend/views/settings/RelaySettings.tsx`

**保留**：
- 指纹测试模块（3 题挑战 + `lmfpd-sdk` 分析 + 记录/请求持久化）
- 采样诊断链路（`errorDetail`、脱敏、堆栈、`ErrorStack` UI）

**新增**：
- 渠道来源改为**实时匿名查询**（不再落盘整份快照）：`GET /api/marketplace/public/channels/search`
- 测试 key 槽（3–5 个），官方口径调用，token 固定商家钉渠道

## 2. 实施阶段

### 阶段 A：砍掉爬取/收藏/标签/路由注册（本轮）

1. 删除文件：`backend/relay/{snapshot,site,traits,client,adapter,providers}.js`；`frontend/views/relay/*`、`frontend/views/settings/RelaySettings.tsx`、`frontend/views/tags/TagEditor.tsx`、`frontend/stores/relay*`、`frontend/service/relay.service.ts`、`frontend/components/{price,tags}.ts`、`frontend/styles/relay.css`
2. 新增 `backend/channel/search.js`：实时渠道查询（匿名、page_size=100、按 total 收敛、30 req/3s 节流、429(HTML) 退避 3s）
3. 新增 Remote `channelsSearch({ model, limit })`
4. 从 `records/service.js` 移除 partitions / tags
5. 从 `shared/contract.js` 移除 partitions*/relay*/tags*，加入 channelsSearch
6. 前端：类型、store、ModelPicker、Panel 等按新结构收敛

### 阶段 B：key 槽 + 官方口径（下一轮）

1. 凭据：`MIT_A6API_KEYS`（JSON 数组，3–5 个），每个 key = 一个并发槽
2. 调度单位改为「模型 × 槽」：一个 key 跑完一个模型的 3 题后交给下一个模型
3. 官方口径：`POST https://api.a6api.vip/v1/{chat/completions|responses|messages}`，`Bearer sk-<key>`，**不带 `-channel` 后缀**
4. 钉渠道：油猴脚本用站点登录态调 `POST /api/marketplace/pin`（`{token_id, model_name, channel_id, fallback_to_smart_routing}`），测完 `unpin`；插件通过本地桥接收 ack
5. 429 分级：区分「平台自助测试配额」「上游限流」「渠道占满」，退避期间样本保持 `waiting`，不计入 `durationMs`

### 阶段 C：验证

- `pnpm build` 通过（TS 诊断 + 静态依赖约束）
- 用 1 个 key 实测官方口径是否绕开 5 次/分钟限额（见调研文档 §8）

## 3. 关键约束（来自实测）

| 约束 | 值 | 来源 |
| --- | --- | --- |
| 渠道查询每页上限 | 500，但 **>100 会丢 `b24`/`b7d`/`cache_hit_rate_24h`** → 固定 100 | 实测 |
| 翻页越界 | 不报错，夹回末页重复返回 → **必须用 `total` 收敛** | 实测 |
| 边缘限流 | **每 IP 30 请求/3 秒**；429 响应体是 HTML，只有 `x-ratelimit-reset: 3`，**没有 `retry-after`** | 实测 |
| 复合主键 | `listing_id + channel_id + supplier_id` | 实测 |
| 可测性 | `test_endpoint` 为空/`unsupported` 不可测；指纹需 `chat`/`responses` | bundle |
| 自助测试限额 | 每账号 5 次/分钟、每渠道 20 次/分钟（服务端判定，前端只做 60s 退避） | 截图 + bundle |

## 4. 不做

- 不再落盘整份渠道快照（1–2 万条），改为按需查询
- 不复刻站点「取密钥」接口（实测会挂起）
- 不绕过平台限额（多账号/多 IP 轮换）
- 不把限流样本当作模型结论（不产出 partial 排名、不打标签）
