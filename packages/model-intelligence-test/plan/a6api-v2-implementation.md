# a6api 专项指纹 v2 实施与验收记录

日期：2026-11-15。对应本次用户确认的“20 个待测项、4 个测试 key 动态槽位”计划。

## 已实施

- 油猴 2.0.0：市场/令牌表格独立 th/td 选择列、当前页全选、跨分页渠道 Map、按 origin+accountId 的测试令牌 localStorage（仅 ID/name）。
- 右上浅色 Shadow DOM 卡片、标题栏拖拽、边界限制、收起与布局记忆；观察器忽略自身变化。
- 元数据监听前移 document-start；支持 fetch 的字符串、Request 与 URL 对象，避免站点提前捕获 fetch 后无法识别令牌 ID。UI 等 DOM 就绪后挂载。
- 复用本机 webServer 的 capability/session 双向桥；账户隔离，限制网页接口只能 selection/poll/ack，不能任意 Remote 或发起模型调用。
- 已核实原生只接受 dsh://open（尾斜线变体同效）。先送选择到 Host，再唤起；Client 常驻轮询用 sidebarRight.openTab 打开专项页。提供实际 Host 的 Web 备用入口。
- 专项手动选择测试令牌对应的 DSH 提供商，不核验 key 身份。普通创建页只有普通 DSH 模型入口。
- 每测试令牌一 worker：pin 关闭 fallback 并回读 → 三题同时用 DSH 提供商采样 → 等全部流结束 → 恢复 → 立即领取下一项。跨任务令牌锁与全局请求池均保留。
- 固定补偿日志、同账号重连恢复、取消不提前复用、固定失败不采样、外部固定变化不覆盖、确定未写入失败 notApplied 清理。
- 补齐运行中的实际 provider、token、等待网页/固定/采样/恢复阶段展示，以及已收到选择的收件箱。

## 验证证据

### 构建

`pnpm --config.verifyDepsBeforeRun=false build` 成功。使用现有依赖，未进行安装或发布；包含 TypeScript、静态分层检查、Host/Client esbuild、统一 CSS 聚合。删除曾由错误 CSS import 遗留的独立 client.css 产物，CSS 由主样式统一注入。

### 本地自动检查：6 项通过

文件：`test/a6-orchestration.test.mjs`，通过 Node 内置测试执行，不调用真实供应商。

1. 20 项 / 4 token：开始 12 条请求，某一三题完成就补位，其他慢槽位保持运行；最终 60 次请求。
2. 取消：三条迭代器未清理完之前，相同 token 不能被另一任务复用。
3. pin 确认失败：零推理请求。
4. 恢复日志持久化：只在相同账号重连时恢复，即使 token 已取消选择仍可收尾。
5. 已证明未发生写入的 pin 失败：清除恢复意图，不锁死该账号。
6. loopback 接口：未配对请求被拒，账号不可串用，提交选择不隐式固定或启动推理，ACK 仅投影允许字段。

调度检查使用可控流与检测器替身来隔离编排，不代表对 lmfpd 算法或真实模型进行了新评测。

## 未验证与部署边界

- 当前运行的 DSH 未自动安装/更新此工作区插件。构建成功只表示本地 bundle 就绪。
- 未在 Tampermonkey 的实际 GM 权限环境中做跨域配对、原生确认框、自动固定与付费采样端到端实测。
- dsh://open 不能切换 Host/profile；安装版必须连接同一 Host，否则使用油猴的 DSH Web 备用入口。
- 站点更改表格结构或接口时仍可能需要适配；无法确认 token 身份时禁选，不猜测、也不读取 API Key 列。
- 用户 key/provider 映射以手动选择为准。官方供应商限流、账单及真实路由结果均需真实测试验证，不宣称已绕过平台任何限制。

## 更新后的使用入口

更新插件、用 integration/a6api-userscript.user.js 替换旧油猴脚本；在 DSH 功能中心复制配对配置，在油猴连接设置粘贴并连接。令牌页选择测试 token，市场选渠道，送到 DSH，在专项页手动选择各 token 的提供商后开始。
