# BTW 旁路提问 · 回归计划（Playwright）

> 目标：不是枚举测试用例，而是按**功能设计**把每条能力走一遍真实链路。
> 前置：插件沙箱已启动（`plugin_dev launch`），运行时有可用模型与凭据（用户注入），
> 浏览器打开沙箱 URL。以下每个「流程」= 一段 Playwright 驱动 + 断言，最后统一跑。

## 0. 断言基线

- 全程 `playwright-cli console` 无 error（插件相关）。
- 主聊天转录中保留旁问命令行（P1 决策：让 `/btw` 的失败原因可见）；成功的旁问不额外产生主线消息。
- BTW 栏与主聊天区域互不影响布局；栏出现/消失不产生主聊天跳变。
- 旁问卡片、主线消息都只通过主题 token 渲染（暗色/亮色切换不破样式）。

## 1. 加载与发现

流程：打开 GUI → 新建会话 → 在输入框输入 `/`。
断言：
- 触发建议中出现 `btw`（或冲突时的 `btw2` / `btw-side`），描述为「旁路提问：基于当前最新真实模型请求上下文独立回答，不打断主线」。
- 无任何旁问时，BTW 栏不占位（输入框上方无空条）。

## 2. 真实请求捕获 → 基础旁问

流程：在主会话发一条普通消息（模型正常回复）→ 等回复完成 → `/btw 用一句话总结刚才的上下文`。
断言：
- 栏自动展开，出现卡片：问题 → 流式文本（▍ 光标）→ done；
- 卡片 provenance 显示「最新真实请求 · <模型> · <N> 条消息 · <时间>」；
- 回答内容与主线上下文相关；
- 主会话不因旁问产生新消息、不被中断。

## 3. 一轮内多次真实请求（关键需求）

流程：让主 Agent 连续执行多个动作（例如：请它依次运行 `pnpm build`、`pnpm test`、读一个文件），完成后 `/btw 刚才这轮实际执行了哪些命令/得到了什么结果？`。
断言：
- 回答覆盖**最新请求消息面**里真实的工具执行结果（而非只按轮次摘要）；
- provenance 的 messageCount 与最新请求规模一致；
- 旁问答案中不出现工具调用（侧问只回答，不执行）。

## 4. 压缩后的等价性

流程：准备一个会触发压缩的长会话（或当前环境 billion-context 压缩生效的会话）→ 触发压缩提交 → `/btw 根据你当前看到的上下文，总结已完成的工作`。
断言：
- 旁问不报上下文溢出；
- provenance messageCount 反映压缩后的消息面（明显小于累计历史）；
- 回答与主会话当前可见/已压缩上下文一致；`compression=inherit` 下无 `DIRECT (uncompressed)` 相关异常；
- 切到设置里把 `compression` 改为 `isolated` 再试：行为可预期（独立归因，不报错）。

## 5. 非干扰与交互

流程：旁问流式进行中，主会话同时输入并发送一条新消息；再对旁问执行 取消 / 重试 / 复制 / 收起 / 展开 / 清空。
断言：
- 主线发送、回复正常，旁问不阻断；
- 取消 → 卡片进入 cancelled；重试 → 同一问题重新流式；复制内容=当前答案；
- 收起后保留 36px 摘要条（问题摘要 + 数量 + 流式指示），展开恢复；
- 清空后栏消失。

## 6. 并发与会话隔离

流程：会话 A `/btw` 未完成时切到会话 B，再 `/btw` 另一个问题；再快速发第 4 个旁问触发并发上限。
断言：
- 两个会话的卡片互不串流；
- 超过 `maxConcurrent`（默认 3）时得到 busy 提示（命令结果或卡片 error）；
- 会话切换后重新挂载 watch，答案继续/恢复，不重复文本。

## 7. 错误路径

流程：新会话不发送任何消息直接 `/btw`；发送空问题；发送超长问题（>4000 字）。
断言：
- 空会话：Failed + 「这条会话还没有任何真实的模型请求，先发一条消息再旁路提问」；
- 空问题/超长：对应中文提示；
- 错误后主会话仍可正常发送。

## 8. 设置页

流程：设置中心 → 「旁路提问」分页 → 修改 `commandName`、`compression`、`maxTokens` 等 → 保存 → 回会话验证。
断言：
- 分页可打开、字段可编辑并即时保存（profile patch 持久化）；
- 改 `commandName` 后新命令名生效（旧名失效，冲突链按 onConflict）；
- 沙箱内为只读态：提示「插件沙箱以命令行 overlay 注入…」，所有控件禁用；
- 正式安装（profile patch 行）后字段可编辑并即时保存，`cordis.patch.yml` 出现该 entry 的 `config`；
- 保存失败/版本冲突有可恢复提示。

## 9. 与旧 btw 插件共存

流程：在旧 `@michengai/dsh-btw` 仍安装时启动 → 观察命令与 slot；卸载旧插件后重启。
断言：
- 共存时本插件命令自动为 `btw2`/`btw-side`（或按 onConflict=disable 时提示未注册），两栏不互相吞并（不同 slot id）；
- 旧插件卸载后恢复 `btw` 主命令；不出现「注册后静默失败」。

## 10. 恢复与刷新

流程：旁问流式中刷新页面 → 重新进入会话；制造一次 carrier 失败（如断网重连）。
断言：
- 刷新后栏按 `state/watch` 重建（P1 不持久化，至少不报错、可继续新旁问）；
- carrier 失败最多自动重试 2 次（≤5s），仍失败则卡片显示可重试错误而非白屏。

## 11. 构建/加载护栏

流程：`node scripts/build.mjs`；启动沙箱检查控制台与插件清单；HMR 修改客户端后刷新。
断言：
- 构建通过；boot manifest 含 `dsh-btw-side/client.js`；
- 控制台无未捕获异常；客户端插件 inject 列表与 manifest 一致；
- HMR 后栏仍在、watch 单消费者、无重复订阅。

---

执行顺序建议：1 → 2 → 5 → 6 → 7 → 3 → 4 → 8 → 9 → 10 → 11（先短链路，后长上下文与并发）。
执行入口：`playwright-cli open <sandbox-url>`；每流程截图留档到 `.playwright-cli/`。
